# 打包流程（标准）

## 在哪台机器上跑（工作关系，20261029 定版）

项目与工具链都在 **Mac mini**（192.168.3.124，M4）的本机盘上；MacBook 侧对 SMB 挂载**只做文档编辑与文件查阅，禁止跑 Gradle**（跨网慢一个数量级 + 文件锁坑）。编译一律 SSH 到 mini 一键驱动：

```bash
ssh nightpoetry@192.168.3.124 '/Volumes/UserData/Projects/LLM/手机部署小模型服务器/scripts/mini-build.sh test'   # 默认=下方两组自检，实测 9s
# 任务：test（默认自检）| assemble（只编不归档）| debug | release | deploy（手机插 mini 时）| stop（停 daemon 释放内存）
```

下文所有 `./scripts/*.sh` 命令同理——在 mini 上执行（或经 mini-build.sh 委托），不要在 MacBook 上对着挂载跑。设计细节见 `docs/设计文档/20261029/01_项目与远程主机构建关系_Mac mini原生编译工作流.md`。

## 版本规则（版本留痕）

- 每次发**正式包**：`android/app/build.gradle.kts` 里 `versionName` **+0.0.1**、`versionCode` **+1**，
  并更新紧邻的 **`// versionNote: <本版本主要升级>`** 注释——打包脚本据此把「版本号 — 升级备注」写进
  `release/CHANGELOG.md`，备注为空会**拒绝打包**（强制每个正式版本都有一句升级说明）。
- 正式包文件名带版本号：`GGUF-Server-release-<versionName>.apk`，放在项目根目录的 **`release/` 文件夹**。
- **旧版本的正式包一律保留**，不覆盖、不删除——`release/` 里按文件名排开就是版本历史。`release/` 里**只放正式包**。
- **调试包也按版本号留档**到项目根目录的 **`debug/` 文件夹**：`GGUF-Server-debug-<versionName>.apk`。
  - 与正式包不同：debug **同版本号允许覆盖**（调试迭代频繁，每个版本号只留最新一份），不强制升版本号。
  - 项目根目录**不再放裸 apk**（不留 `GGUF-Server.apk`）：`deploy.sh` 直接读当前 `versionName`、装 `debug/GGUF-Server-debug-<版本>.apk`。

## 打包前先跑两组自检（几秒，别省）

```bash
source /Volumes/SystemData/gguf-toolchain/env.sh
"$GRADLE" -p android :app:testDebugUnitTest    # 宿主纯逻辑：切面分发纪律/curate 语义、流式标记扫描器
node scripts/check-plugins.js                  # 内置插件 JS：curate 快判定、heavymem 计算两段式
```

覆盖的都是**真机验收撞不到的路径**（模型不肯自发吐 `<tool>`、不方便现场给插件注错），
在 Mac 上是秒级的事。真机时间只该花在真机才验得了的事情上。

## 正式包（release）

```bash
# 1. 先改版本号（+0.0.1 / +1）和 versionNote，否则脚本会拒绝执行
vim android/app/build.gradle.kts     # versionCode / versionName / // versionNote: <本版本主要升级>

# 2. 一键打包
./scripts/release.sh
# 产物：release/GGUF-Server-release-<版本>.apk（脚本发现同名文件会报错——说明忘了升版本号）
#      release/CHANGELOG.md 自动追加「- **v<版本>**（日期）— <versionNote>」
```

脚本做的事：读 `versionName` 和 `// versionNote` → `source env` → `$GRADLE assembleRelease`
→ 把 `app-release.apk` 拷进 `release/`（文件名带版本号）→ 把「版本号 — 升级备注」追加进
`release/CHANGELOG.md`（最新在最上、同版本不重复）。缺 versionNote 直接报错退出。

- 签名：`signingConfigs.release` 已硬编码在 `app/build.gradle.kts`，keystore 在
  `android/keystore/ggufserver-release.jks`（主备份：`/Volumes/UserData/秘钥存储/安卓秘钥/GGUF服务器/`）。
- **不要把正式包装到开发机**（签名与 debug 不同，必须先卸载 → 会清掉会话和已导入模型）。
  正式包给分发用；开发机永远用 debug 包。

## 调试包（debug）

```bash
# 一键打包 + 版本化归档（推荐）
./scripts/debug.sh
# 产物：debug/GGUF-Server-debug-<版本>.apk（同版本号覆盖）
```

脚本做的事：`source env` → `$GRADLE assembleDebug` → 拷进 `debug/` 文件夹（文件名带版本号）。
`deploy.sh` 会读当前版本号、装 `debug/GGUF-Server-debug-<版本>.apk`。原生库变更时改用 `./rebuild.sh`，它也会归档到 `debug/`。

手动等价流程：

```bash
source /Volumes/SystemData/gguf-toolchain/env.sh
VER=$(grep -o 'versionName = "[^"]*"' android/app/build.gradle.kts | cut -d'"' -f2)
cd android && $GRADLE assembleDebug
cp app/build/outputs/apk/debug/app-debug.apk "../debug/GGUF-Server-debug-$VER.apk"
adb install -r "../debug/GGUF-Server-debug-$VER.apk"
```

装完记得处理孤儿进程（install -r 会把 llama-server 留成孤儿占着端口）：

```bash
adb shell "run-as com.ggufserver.app sh -c 'kill \$(pidof libllamaserver.so)'"
```

## 原生库变更时

改了 llama.cpp 或要更新 `libllamaserver.so` 等 jniLibs 时，用 `./rebuild.sh`（原生 + APK 全量重建），
其余情况只跑 gradle 即可。

## 内置插件资产变更时（重要）

改了 `assets/plugins/<id>/` 下的任何文件（ui.html / service.js / icon.png / manifest），
**必须同时把该插件 manifest.json 的 `version` 升一位**——已装设备上的释放逻辑
（`PluginStore.releaseBuiltin`）对相同版本号直接跳过，不 bump 版本的话改动永远
到不了真机（表现为「明明改了却没生效」）。插件版本与 App 版本相互独立。
