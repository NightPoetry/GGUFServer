# 设计文档 · 编写规范（项目模板）

> 本文档是本目录**所有记录性文档（设计/迭代/复盘/方法论）的编写准则**。就地建体系时拷贝本模板到项目设计文档目录（如 `开源设计文档/README.md` 或 `docs/设计文档/README.md`），按项目实际改写括号占位。
> 哲学：**在 AI 时代，设计原话与设计文档比代码更重要——代码是设计的投影，原话才是意图的本源。** 文档要写到「源代码全丢，只留文档也能重建」。

## 1. 核心原则（最高优先级）

### 1.1 设计原话比代码重要

每篇文档必须**逐字保留**需求方的设计原话（原始句，不改写、不转述、不打码）。原话放文档**最前**（§0），作为意图本源；后续语义提炼、方案、代码都只是对它的展开。笔误、口语、情绪句一律保留（笔误旁注真实语义，不改原文）。

### 1.2 原文 + 浓缩总结 + 可重塑

1. **原文必录**：每一轮需求的设计原话逐字进 §0，多轮按时间续录。
2. **浓缩必写**：§1 语义提炼 + §3 关键决策 Why 用可执行语言复述，不是把原话再抄一遍。
3. **可重塑**：写到「源代码全丢，只留文档也能重建」——数据（SQL）、规则（守卫/归一化/资金）、接口（路径+入参+返回要点）、界面、文案 key、验证六件齐备（每篇设「重建清单」节）。
4. **全盘托出可交付**：整套文档本身就是可交付资产，接手方照它即可复现系统行为与决策链路。

### 1.3 文档为准绳 · 方法论优先 · 诚实记录

- 任何重构/重写/AI 复现以文档为准绳——决策、取舍、Why 落成文字。
- 能上升为可迁移方法论的内容独立成篇，项目场景只作实例。
- 踩坑、反复、推翻、事故如实写入（含版本与触发点）。

## 2. 目录与命名

```
<文档目录>/
├── README.md            # 本文档
└── <YYYYMMDD>/          # 按设计定稿日期分目录
    └── NN_主题.md       # NN 全局递增（跨日期目录连续不重复）；同主题迭代沿用原号
```

每篇文档顶层用**一句话**点出本质，方便扫目录即知。

## 3. 标准结构（八件套）

```markdown
# NN · 主题
> 版本：vX.Y.Z 初版 · vX.Y.W 定稿入库（YYYY-MM-DD）｜关联：其余相关文档号
> 一句话：<本质>

## §0 设计原话（逐字，YYYYMMDD）
## §1 语义提炼
## §2 算法 / 数据 / 接口
## §3 关键决策 Why（每项标注「别改这里，会重新打开 XX」）
## §4 验证（命令+断言+实测数字；没验证写「未验证」；上线后回填生产验证）
## §5 文件索引
## §6 版本履历
## §7 重建清单（语义/数据/规则/接口/界面/验证 + 刻意不做）
```

骨架由脚手架生成：`node ~/.agents/skills/design-archive/scripts/new-design-doc.js "主题"`。

## 4. 一致性检查清单（提交前过一遍）

- [ ] §0 原话**逐字**保留，未改写/转述（笔误原文保留 + 旁注）
- [ ] §1/§3 是「我的浓缩总结」，不是原话复述
- [ ] 可重塑：数据/规则/接口/界面/文案/验证六件齐备
- [ ] Why 已写，且标注了「别动这里」的地方
- [ ] 事故/踩坑/多轮修正已记录
- [ ] 版本履历补上了本次版本行
- [ ] 关联文档互相指引（`见 NN 号 §X`）
- [ ] 与代码**同一提交**入库

## 5. 冲突标注与追溯

新设计与老设计结论冲突/取代时：

```bash
node ~/.agents/skills/design-archive/scripts/design-supersede.js <老号> <新号> "冲突范围"
node ~/.agents/skills/design-archive/scripts/design-supersede.js check   # pre-commit 也校验
```

老档顶部出现 ⚠️ 冲突标注（指向新档），新档履历记追溯——可追溯、防冲突、防悬空引用。

## 6. 工作流联动（与 git 一起）

- 设计定稿/修订**必须与代码同一提交**（版本号一致），不可先出代码后补文档。
- 门禁安装（每项目一次）：

```bash
mkdir -p scripts/git-hooks
cp ~/.agents/skills/design-archive/hooks/pre-commit scripts/git-hooks/
chmod +x scripts/git-hooks/pre-commit
git config core.hooksPath scripts/git-hooks
```

- 记录性文档的 commit 用 `docs:` 前缀并在括号注文档号（如 `设计文档NN`）。
