# 设计文档07 · 模型市场视觉统一、量化下拉、判定修复与入口遮挡修复

## §0 设计原话（逐字）
> 「它那个模型市场啊，里边的按钮不是很漂亮。因为那个可运行和推荐以及下载按钮吧，它的风格不是很统一。而且它这个胶囊体放在这也不是很漂亮，你自己掂量掂量。还有就是 全部 多少个量化？它得像个下拉列表才行，不能让用户去猜它是个下拉列表。」（2026-11-16）
> 「还有就是它那个模型市场，那个搜索输不进去内容，就输不进去字。搜索是坏的搜索功能，这个也得修修。」（2026-11-16）
> 「还有就是它这个。勉强运行什么的。请你以 真正的模型去判断。比如说千万三点八27B，手机肯定是勉强运行的。但是它里边有一个 I M A T R I X U N S L O T H 点 G G U F 只有13兆。它就直接把它判定为可运行，这就太奇怪了。那个13兆的 gduf 肯定不是本体，你分析分析那是个什么东西？」（2026-11-16）
> 「还有就是那个插件管理也没法打开了，就是你得确保每个按钮和菜单它都是正常的才行，功能是不能退化的。」（2026-11-16）

## §1 语义提炼
四件事：①行内视觉语言统一（判定徽标/信息胶囊/下载按钮/量化展开控件同一套胶囊语法）；②「全部 N 个量化」从裸文字改成有明确下拉形态的控件；③判定修复：仓库附带的 imatrix 校准文件（13MB 级）不得判「可运行」抢推荐位，27B 级本体应判「勉强」；④插件管理入口点击后被设置内容盖住（视觉上"打不开"）；⑤搜索框输入问题（对齐已知可用形态的消除性修复）。

## §2 算法/数据/接口
1. **判定（ModelHub.kt）**：
   - `parseTree` 新增排除 `path.contains("imatrix", true)`（与 mmproj 同款）——imatrix=量化校准的重要性矩阵统计文件，不可运行；
   - `judge` 的 best 挑选改双保险：`runnablePool = verdicts.filter { it.quant != null }`，best 只从有效量化命名的文件里挑（ok 优先、无 ok 取 tight）。
2. **插件管理遮挡（SettingsScreen.kt）**：`if (showPluginManager) { PluginManagerScreen(...); return }`——补 return 与 showHub 同构；原缺 return 时设置内容同根级后绘制盖在插件页上。
3. **UI 胶囊语法（ModelHubScreen.kt）**：语义徽标（可运行/勉强/带不动）=语义色 9% 底+40% 边+11sp SemiBold 字、padding 9×2.5；信息胶囊（推荐 xx·大小/文件大小）=card 底+line 边+11sp ink2 同 padding；下载按钮=accent 实心 999 胶囊 11.5sp SemiBold 白字、14×4；行内下载=同语法缩版；「全部 N 个量化」=card 底+line 边胶囊+ExpandMore/ExpandLess 图标随状态切换，点击开合内嵌量化面板。
4. **搜索框（ModelHubScreen.kt）**：对齐 ChatScreen 已验证形态——加 `cursorBrush=SolidColor(accent)`、decorationBox 用 `Box { if(empty) Text; inner }` 显式包裹、胶囊化（999 圆角）、`keyboardActions=KeyboardActions(onSearch=submitSearch)`（键盘搜索键直提交）、搜索按钮同胶囊化。

## §3 关键决策 Why
1. imatrix 走 parseTree 排除而非仅判定降级：它本来就不该出现在「选一个下载」的清单里（用户会拿它当模型下载，13MB"省流量"陷阱）；judge 层 quant!=null 双保险防其它命名变体漏网。
2. best 限定 quant!=null 而非排除特定关键词：关键词枚举永远追不完变体，「有效量化命名」是可判定的结构特征。
3. 插件管理用 return 而非调 Z 序：与 showHub 同构最小 diff；Z 序修补（defer/ zIndex）属过度工程。
4. 搜索框消除性修复：无法在退化模拟器环境稳定复现（技术发现007 输入管线间歇冻结），故把与已验证可输入的 ChatScreen 形态的全部差异点（cursorBrush 缺失/decorationBox 裸平铺/直角样式）一次抹平，真机验证收敛。
