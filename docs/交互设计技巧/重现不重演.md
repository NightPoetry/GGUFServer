# 重现不重演：内容再次出现时，不要重放它当初的动静

## 本质

因果对应：一切动静必须能被用户归因到自己刚才的动作上。找不到"因"的动静
会立刻产生失控感，而失控感是交互里最贵的代价——一次就够用户从此提防这个功能。

## 技巧

带自动副作用的内容（自动播放声音、自动弹面板、自动跳转），副作用只属于它
"第一次发生"的那一刻。之后无论内容因为什么原因再次出现——翻回去看、重开会话、
列表滚动导致的界面重建——都只能安静地显示，不能把当初的动静再演一遍。

## 例子

语音消息卡片有自动播放：模型发来一条语音，气泡出现的同时就开始说话，这是符合
预期的——用户刚要了语音，声音立刻来了。但卡片是网页容器，随着聊天列表滚动会被
回收再重建：往上翻两屏再翻回来，这个气泡其实是刚刚"重新出生"的。如果重建也触发
自动播放，用户翻个聊天记录，三天前的语音突然开口说话——没有比这更吓人的了。

解决办法是卡片数据里带一个出生时间戳，自动播放前先看看自己"新不新鲜"：
产生至今不到二十秒才播，超过就只安静地显示气泡。翻记录翻出来的旧语音，
点一下才出声。

## 分析

用户对因果的直觉是：动静必须由我刚才的动作引起。刚要了语音就响，因果清晰；
翻记录时突然响，用户找不到"因"，第一反应是失控——失控感是交互里最贵的代价，
一次就能让用户从此提防这个功能。

实现层面的教训是：界面元素的"重建"对系统来说是常态（滚动回收、进程重启、
会话重开），但对用户来说这些技术性重建根本不存在——他看到的只是"东西还在那儿"。
所以副作用不能挂在"元素被创建"这个技术事件上，必须挂在"事情真正发生"这个
用户视角的事件上。时间戳判新鲜是最简单的落地方式。
