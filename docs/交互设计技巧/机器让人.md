# 机器让人：自动行为永远给用户的手动意图让路

## 本质

自动化是替用户省事，不是替用户做主。用户一旦亲手表达了别的意图，
所有自动行为立刻退后；想恢复自动，给一个明确的开关，而不是让系统猜。

## 例子

流式回复的滚动跟随：模型逐字生成时，列表贴着底部自动跟随，新内容一出来就能看到——
这是自动化在省事。但用户往上翻看历史消息时，自动跟随必须立刻停止，否则手指刚滚上去
两屏，下一个字生成时又被拽回底部，等于机器在跟人抢方向盘。

这个功能走过弯路：曾试图靠几何推断"用户是不是还想跟随"（离底部近就跟、远就不跟），
结果 Markdown 重排（代码块突然撑开）会在一帧内把底边推过阈值，被误判成"用户离开了
底部"，跟随从此失灵。最终方案放弃了所有猜测：贴底时由布局系统天然锚定底边（零滚动
调用，顺带根治了逐字滚动的闪屏），用户滚走就是滚走了，想回去点一下浮出的「回到底部」
按钮——把"恢复自动"做成一个明确的手动动作，而不是一个猜出来的状态。

## 分析

人机抢方向盘是最恶劣的交互体验之一，因为它每一次发生都在告诉用户"你说了不算"。
而反过来，自动行为退后的代价几乎为零——用户多点一下「回到底部」而已。两边的代价
如此悬殊，规则就很清楚：宁可自动化少干活，绝不让它压过手动意图。

另一个教训是"猜用户意图"这件事本身：猜测型状态机总会遇到猜错的一帧，而一个
显式按钮永远不会错。当推断的复杂度开始超过一个按钮时，就该用按钮。
