# 非对称交互：触发要小，展开要大

## 本质

成本和收益分开算账：入口的大小跟着"误触的代价"走，回报的大小跟着"意图的确定性"走。
两者没有理由相等，强行对称反而两头都不舒服。

## 技巧

一个交互的「入口大小」和「结果大小」不必对称，也不应该对称。容易误触的手势入口要收窄，
但用户一旦明确表达了意图，给他的回报要足够大方。

## 例子

顶部门户面板（卷帘门）的下拉手势：触发热区只占消息区最上面的 1/4——手指必须从靠近顶栏的
位置往下拉才会开门户；但面板拉开之后占大约三分之二屏，足够舒展地放下插件界面。

这个数字是试出来的。曾经把热区扩大到消息区的 2/3，想让门户"更容易打开"，结果适得其反：
翻聊天记录本来就是在屏幕中部上下滑，热区一大，往下翻两下就不小心把插件面板拉出来了，
"更容易打开"变成了"总是被迫打开"。于是热区改回 1/4，而面板展开的高度一点没缩——
太短的面板等于让用户开了门还得弯腰进去。

## 分析

入口大小的依据不是"点起来方不方便"，而是两头的平衡：误触的概率乘以误触带来的烦躁，
对比真要用的时候找不找得到。下拉开门户是个低频动作，入口窄一点用户完全负担得起；
而误触是高频场景（翻记录）里的高频干扰，一次都嫌多。

结果大小的依据则相反：用户完成了一个明确的、不会误触的动作，说明意图是确凿的，
这时候小气反而是错——面板给小了，用户还要再拖一次拉大，等于把一次意图拆成了两次操作。

现实里的卷帘门就是这个结构：拉手只是一条窄边，门帘展开是一整面墙。人对这种
"小把手、大结果"的结构毫无学习成本，因为物理世界到处都是。
