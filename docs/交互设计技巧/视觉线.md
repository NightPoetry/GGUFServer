# 视觉线：元素沿共同的基准线排布，槽位提前算好，留白两端对称

## 本质

眼睛会自动寻找对齐：同一条竖直线上的东西被感知为"一列"，齐了就整洁，
差几个像素就"说不上哪里不对但很难受"。基准线和槽位是提前算好的骨架，
内容只是现场填进去——骨架恒定，无论填多填少，画面都是稳的。

## 例子

顶栏图标的排布规则：整行两端对齐、间距均匀分布；每行能放几个图标、每个位置
在哪里都按屏宽提前算好（44dp 一个槽位，固定功能区占五个，剩余全归插件直显槽），
图标只是现场填充进槽位——满员时正好铺满一行，不满时也均匀铺开。改版前的问题
正是反例：图标全部靠右挤着，左边空出一大块，"很不美观"。

基准线还要跨区域延伸：顶栏最左边图标的图形边缘，与下方消息列表里头像的左边缘
落在同一条 18dp 竖直线上——顶栏和内容区左边留的空间相同，整个屏幕从上到下
共享一条视觉线。计算时注意对齐的是"图形的视觉边缘"而不是控件的触控盒：
44dp 的槽位里图形居中、自带约 10dp 透明留白，容器只需缩进 8dp，图形恰好落线。

## 分析

对齐的失败几乎不会被用户明确指出来，只会被感觉到——"不整齐""空着一块"
"说不出的别扭"。所以它不能靠事后目测修补，要靠规则一次算清：留白多少、
槽位多宽、最多几个、超出怎么办（收进启动台）。规则算清之后，动态内容
（插件随用户启停增减）怎么变都不会破坏画面，这正是"骨架恒定、内容填充"
的价值：美观不是每次摆出来的，是被规则保证的。

另一个容易踩的坑是拿触控盒对齐：触控盒为了手指够大（44dp），图形为了视觉
够轻（22dp），两者天生不同宽。对齐永远以肉眼看到的图形边缘为准。
