# 重点会跳出来：信息按轻重分层呈现，要紧的自己跳出来，不靠用户逐条读

## 本质

把十条信息平铺给用户，等于让用户自己当编辑。分层的本质是把"哪条要紧"这个
判断在设计时就做完：轻的退成背景，重的加权跳出，用户扫一眼就拿到重点。

## 例子

插件启用前的权限确认弹窗：权限清单按风险分三级着色——低风险（调用本机模型）
灰色圆点，中风险（读取当前会话、注入上下文）黄色，高风险（读取全部历史会话、
接管对话回合、访问公网）红色，而且只有高风险条目才在下面多一行解释文字。
用户可以不逐条读完清单，但"读取你的全部历史对话记录"这样的条目一定会撞进
视线——红色加多出来的那行字，就是它该有的重量。

同一原则的日常版是消息下方的辅助信息：生成速度用 10.5sp 的淡灰小字标在角落，
存在但绝不抢戏；插件的确认条（"已记入便签"）是带图标的浅底小条，与正文
一眼可分——各类信息都待在与自己重要程度相称的视觉层级上。

## 分析

风险分级的关键决定是"只给高风险加解释"：如果每条权限都配一段说明，弹窗变成
一篇文章，用户直接全文跳过，红色条目反而被淹没。克制低风险条目的存在感，
才买来了高风险条目的注意力——分层是零和的，什么都强调等于什么都没强调。

判断层级的标准不是信息"是什么"，而是"用户此刻需要为它做什么"：需要慎重决定的
（高危权限）给最重的视觉；知道了更好的（速度、确认）给最轻的；介于中间的，
宁轻勿重——因为加重是廉价的诱惑，每个功能的作者都觉得自己的信息最重要。
