# 变化不瞬移：界面变化要么跟着手指，要么有过渡，绝不瞬间跳变

## 本质

人眼靠连续性理解运动：一个东西从哪来、到哪去，中间的路径就是解释本身。
瞬间出现的东西没有来路，用户要额外花一拍去搞清"刚才发生了什么"——
过渡动画不是装饰，是把这一拍的认知成本预付掉。

## 例子

顶部门户面板的展开经历过两个版本。早期版本是阈值触发式：手指下拉超过某个距离，
面板"啪"地整个弹出来（用户原话："往下拉时突然出来就很奇怪"）。改进后的版本是
卷帘门式跟手展开：拉动过程中面板高度实时跟着手指的进度走，过了阈值就顺势展开
到位，动画曲线接着手指松开时的速度继续——面板不是"出现"的，是被用户"拉出来"的。

同样的原则也管收起和联动：键盘弹出时，门户和消息区一起平滑收缩给输入框让位，
而不是突然重排；插件管理页展开某个插件的设置时，页面平滑滚动把那一行送到屏幕
顶端，而不是瞬间跳过去。

## 分析

跟手和过渡是两档，按交互类型选：手势驱动的变化（拉面板、滑抽屉）必须跟手——
手指和画面绑定，用户获得的是"我在直接操纵这个东西"的实感，这比任何动画曲线
都更直觉；点击驱动的变化（展开、跳转）用短过渡——一两百毫秒，够眼睛建立
"从哪来到哪去"的连续性就行，再长就变成等待。

反面是两个极端：零过渡的瞬移让用户丢失空间感，过长的动画让用户等系统表演。
两者共同的错误是把节奏的主导权从用户手里拿走了。
