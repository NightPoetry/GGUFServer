# 状态挂在脸上：系统内部的状态变化，界面上必须有外显信号

## 本质

用户模型和系统状态不同步，是大多数"这软件是不是坏了"错觉的来源。
内部状态一旦可能影响用户的判断或操作，就要在界面上留一个低打扰的外显信号，
让用户扫一眼就能同步，而不是操作失败后才发现。

## 例子

两个例子，一明一暗。

明的是服务器状态灯：顶栏服务器图标的小灯，绿色常亮是"在线待命"，绿色呼吸闪烁是
"正在处理请求"（本机聊天和局域网请求都算），橙色闪烁是"重启配置生效中"。用户不用
点进任何页面，扫一眼顶栏就知道服务活不活、忙不忙。这个语义还纠正过一次：最初只有
本机对话才闪，远程请求不闪——但灯表达的应该是"服务器忙"这个状态本身，而不是
"我在跟它聊天"，后来统一了。

暗的是参数导演插件：它启用后会按任务类型悄悄改写实际生效的采样参数，配置抽屉里的
温度滑杆就"失效"了。如果什么都不说，用户拖滑杆发现没效果，第一反应是滑杆坏了。
解决办法是在滑杆旁边加一行说明："参数导演已启用，本机聊天按任务自动调参，
以上滑杆仅作兜底默认值"——一句话把"控件失灵"的错觉消解成"哦，被接管了"。

## 分析

第二个例子比第一个更重要：当一个功能会改变另一个控件的行为时，被改变的控件旁边
必须有说明。用户对"控件坏了"的容忍度远低于对"功能被接管"的容忍度——前者动摇的是
对整个软件的信任，后者只是一条新知识。外显信号的成本是一行小字，挽回信任的成本
是无数倍。信号本身要低打扰：常亮/闪烁、一行灰字，都是"想看就在、不看不吵"的形式。
