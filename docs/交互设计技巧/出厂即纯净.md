# 出厂即纯净：默认状态是最少惊讶的状态，能力全部由用户亲手打开

## 本质

默认状态是用户还没来得及表达任何偏好时软件替他做的选择，所以它必须是
最没有惊讶、最不越权的那个：不悄悄干活、不悄悄收集、不悄悄变慢。
附加能力的每一次开启都应该是用户亲手做的、知情的决定。

## 例子

这个 App 的所有插件——包括自家内置的便签、记忆、朗读——安装后全部默认禁用。
出厂状态下的对话是"裸流式"：没有意图路由、没有提示词注入、没有后台检索，
请求路径干净到没有一行插件相关的代码在跑。想要记便签、跨对话回忆、语音朗读，
用户自己去插件管理页打开，打开时还会看到一份按风险分级着色的权限清单
（读全部历史会话、接管对话回合这类高风险条目标红并附一句解释）。

这条底线在工程上也是硬性的：零插件时的发送路径被规范写成红线——"没有正则路由、
没有额外调用、没有附加条款，这是硬性保证，不是优化目标"。

## 分析

默认全开看起来是在"展示功能"，实际是在透支信任：用户发现软件悄悄注入了提示词、
悄悄读了历史记录、回复莫名变慢，每一次"这是什么时候开的？"都是一次信任扣分。
默认全关则把因果关系还给用户——开了什么，什么才生效；变慢了，是自己刚开的
那个东西导致的。软件行为始终能被用户自己的决定解释，这就是"最少惊讶"。

亲手打开还有个附带好处：用户开启时读过权限清单，等于完成了一次微型的知情同意，
后面再看到这个插件干活（确认条、角标、卡片），都在预期之内。
