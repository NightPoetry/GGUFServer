# 手势分家：一个手势一个地盘，靠划地界解决冲突，不靠猜优先级

## 本质

手势的歧义没法靠"聪明的判定"消除，只能靠空间上互不重叠来消除。每个手势
有自己专属的地盘，用户按位置就能预测结果，不需要理解系统内部的仲裁规则。

## 例子

这个 App 的手势打过三次架，三次都是靠划地界解决的：

一次是插件面板收不起来还裁内容——旧方案在面板整体上挂了"上滑收起"手势，
把插件网页内部的滚动全吞了（用户反馈"UI 被挤裁切、内部没法滚动"）。解决办法
是面板本体一个手势都不挂，收起的唯一手势入口收窄到底部一条 26dp 的卷帘门拉手：
拉手是收起的地盘，拉手以上全是插件自己的地盘。

一次是操作插件面板时总把左右抽屉误拉出来——系统抽屉的内置手势默认覆盖全屏。
解决办法是抽屉关闭时禁用内置手势，开抽屉只走消息区自己识别的横滑：消息区是
抽屉手势的地盘，面板区不是。

一次是竖直方向三个动作抢一条轴（下拉开门户、列表滚动、翻看历史）——解决办法
是门户只认"起手点在消息区上 1/4 且方向朝下"的拖动，其余全部留给列表。

## 分析

被吞过一次手势的用户会形成"这里不能滑"的错误肌肉记忆，而且这种记忆很难纠正——
所以手势冲突的代价比看起来大得多。划地界的方案好在结果完全可预测：手指落在哪，
归谁管，一目了然。技术上也更稳：判定优先级的方案总有边界情况（斜着滑、慢慢滑），
地盘方案没有边界情况，因为地界本身就是边界。
