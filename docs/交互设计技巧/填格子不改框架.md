# 填格子不改框架：扩展内容只能填进预留的格子，不能碰原版框架

## 本质

交互风格的一致性。一致的框架让用户"不用想"——头像永远在那、按钮永远在那，
这些恒定的东西不占认知；一致性被破坏一次，用户就要把整个界面重新拿出来打量一遍。

## 技巧

给第三方（插件、模型、外部内容）开放界面时，开放的是一个边界清晰的"格子"，
格子里面随便发挥，格子外面的一切——头像、间距、动作行、整体布局——寸土不让。

## 例子

插件消息卡片：插件可以在对话里插入一条完全自绘的消息（比如语音气泡，样式、动画、
点按长按行为全是插件自己的 HTML 写的），但这条消息的头像还是标准的助手头像，
下面还是标准的复制按钮和角标，行间距和普通消息一模一样。

第一版实现时曾把卡片消息的头像换成了插件自己的图标，看起来是个贴心的细节——
"让用户知道这条消息来自哪个插件"。但立刻被否了：头像是对话框架的一部分，
插件一旦能改头像，这条消息看起来就不再是"对话的一部分"，而像一个第三方广告位；
而且十个插件十种头像，对话列表的视觉节奏就碎了。改回统一头像后，语音气泡
和普通文字消息在列表里自然混排，谁也不觉得突兀。

## 分析

用户对一个界面的信任感来自框架的稳定：头像永远在左边、复制永远在消息下面、
消息永远一条一条往下排。这些恒定的东西是用户"不用想"的部分——认知负担最小的
状态就是根本不需要认知。扩展内容如果能改动框架，每条消息都变成了需要重新打量的
未知物，用户被迫把"不用想"的事情重新拿出来想。

划边界还有个好处：格子里的自由反而更彻底了。正因为插件碰不到框架，宿主才敢放心地
把格子里的渲染权全部交出去——双方都清楚哪里是谁的地盘，才不需要互相防着。
