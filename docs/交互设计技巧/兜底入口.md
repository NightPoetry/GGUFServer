# 兜底入口：快捷方式可以做减法，但入口永远不能清零

## 本质

可达性恒定：用户只需要记住一条永远有效的路径，其余快捷方式全是纯增益。
"这个功能现在从哪进"是一种本不该存在的知识，兜底入口把它从用户脑子里删掉了。

## 技巧

同一个功能可以有多个入口：手势、快捷图标、菜单。快捷入口可以按需增减
（省空间、防误触、用户自定义），但必须保证有一个稳定、完整、永远在场的兜底入口，
任何配置组合都不会让功能变成"进不去"。

## 例子

插件面板的入口有三层：边缘手势（最快）、顶栏图标（直观）、启动台（兜底）。
顶栏宽度有限，图标按屏宽自适应，放不下的收进启动台；插件也可以声明"不占顶栏"
（比如朗读插件，它的主战场在消息角标上，面板只是说明页，不值得占一个顶栏位）；
手势区间冲突时会自动降级为无手势。但无论怎么减——不占顶栏、没有手势、屏幕再窄——
启动台永远列出全部已启用插件，点开就能进面板。

所以做"朗读插件不占顶栏"这个决定时不需要任何犹豫：拿掉的只是一条快捷方式，
不是入口本身。

## 分析

快捷入口的取舍常常陷入两难：留着占地方、去掉怕用户找不到。有了雷打不动的兜底层，
这个两难就解开了——上层的所有取舍都变成纯优化，做错了顶多是"多点一下"，
而不是"功能失踪"。用户侧的心智也简单：记不住手势没关系，记住"启动台里什么都有"
这一条就够了。找东西的兜底路径只有一条、永远有效，这本身就是认知负担最小的结构。

反过来说，如果每个入口都可有可无，用户就得记住"这个功能现在从哪进"这种
本不该存在的知识——配置的自由变成了记忆的负担。
