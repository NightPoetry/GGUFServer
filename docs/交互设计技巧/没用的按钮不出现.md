# 没用的按钮不出现：控件只在它有意义的时刻存在

## 本质

一个此刻点了也没意义的控件，不是"备用"，是噪音——它占着视线、诱导无效点击，
还迫使用户思考"这个现在能点吗"。语义不成立的时刻，控件就不该在场。

## 例子

消息下方的动作行（复制、朗读、重试）有两条隐形的出场规则：

一是流式生成期间整排动作行都不出现。内容还没定型，复制复制到一半的话没意义，
朗读读一半的话更怪；等流式结束动作行才浮现，此刻每个按钮点下去都是完整语义。

二是「重试」和候选切换 ‹K/N› 只出现在最后一条助手回复上。中途某条历史回复如果
允许重试，它后面的对话就失去了依附的上下文——这个操作在语义上根本不成立。
与其放一个点了之后需要解释"为什么不行"的按钮，不如从一开始就不给入口。

同样的规则也约束模型：工具调用协议里明确要求"没有明确需要时绝不输出标记"——
连 AI 的"按钮"（工具标签）都遵守同一条出场纪律。

## 分析

常见的错误做法是控件常驻、时机不对就置灰。置灰解决了误操作，没解决认知负担：
用户还是要看到它、绕过它、偶尔忍不住点一下再琢磨为什么点不了。直接不渲染
则把这些成本全部归零，界面在任何时刻展示的都是"此刻真正可用的动作全集"——
这本身就是一种诚实：界面不对用户撒谎，也不让用户做无效的猜测。

判断标准很简单：问一句"用户此刻点它，我能给出有意义的结果吗"，答不上来就藏起来。
