# GGUF 插件开发指南

> 面向想给本 App 写插件的开发者的实用指南。规范性细节（预算数值、校验规则的
> 权威口径）以《工具插件规范.md》为准；本文是它的「上手版 + 速查版」。
> 当前桥接口 `apiVersion = 1`（App ≥ 1.1.2 含消息角标与 topbar 配置）。

## 1. 三分钟上手：最小插件

插件 = 一个 zip 包（≤ 20MB，后缀 `.zip` 或 `.gtool`），最少四个文件：

```
my-plugin.zip
├── manifest.json     # 身份 + 权限 + 声明（见 §3 速查表）
├── icon.png          # 96×96，白色图形 + 透明背景（宿主按主题着色）
├── ui.html           # 插件面板页（纯后台插件可以是一个说明页）
└── service.js        # 可选：声明了 hooks 时必需，后台逻辑
```

最小可运行的 manifest（纯 UI 插件，零权限）：

```json
{
  "id": "com.example.hello",
  "name": "示例",
  "version": "1.0.0",
  "apiVersion": 1,
  "entry": { "ui": "ui.html" }
}
```

安装：设置 → 插件管理 → 导入插件（选 zip）。所有插件安装后**默认禁用**，
用户在管理页手动启用（启用时会展示你声明的权限清单）。

技术栈就是普通网页：ui.html / service.js 跑在 WebView 里，宿主在页面加载前注入
`window.gguf`（Promise API，见 §6）。**不要也不需要**任何构建工具或框架。

## 2. 插件能出现在哪里（露出面总表）

「插件在界面上以什么形式存在」全部由 manifest 声明式控制：

| 露出面 | 出现条件 | 控制字段 | 说明 |
|---|---|---|---|
| 顶栏图标 | 启用 且 `panel.topbar ≠ false` | `panel.topbar`（默认 true） | 直显数量按屏宽自适应，放不下的自动收进启动台；纯角标/纯后台插件建议声明 `false` 不占位 |
| 启动台方格 | 启用（恒有） | 无（不可关） | 顶栏「启动台」下拉的方格面板，永远列全量——插件面板的兜底入口 |
| 门户面板（ui.html） | 启用（恒有） | `entry.ui`、`panel.size` | 顶部下拉门户里的一个选项卡；同刻只开一个面板 |
| 边缘手势 | 启用 且 声明了手势 | `gesture`（edge/range/threshold） | v1 只支持 top 边缘；区间冲突时降级为无手势（图标仍可用）；用户可在管理页改区间 |
| 设置卡片 | 启用 且 声明了设置页 | `settingsCard` | 插件管理页展开该插件时渲染的常驻配置卡片（自适应高度） |
| **消息角标** | 启用 且 声明了动作 | `messageActions[]` + hook `messageAction` | 消息下方动作行（复制/重试那排）的小按钮，点击把**该条消息**交给插件 |
| **消息卡片** | 工具返回 card / `gguf.card.post` | 权限 `chat:card` | 对话里一条由插件 WebView 自绘的消息（语音气泡、图表、小组件…）——样式与交互全归插件，点击/长按/滑动就是卡片页里的标准 DOM 事件 |
| 确认条（notice） | 钩子/工具返回 notice | 运行时返回值 | 📌 图标小条，附在消息下方，不混入正文 |
| toast / 数字角标 | 运行时调用 | `gguf.ui.toast()` / `gguf.ui.setBadge(n)` | 轻提示；数字角标画在自己顶栏/启动台图标右上角 |

**设计原则**：露出面全部 opt-in（声明才有），入口永不为零（启动台兜底），
用户的手动配置（手势区间等）覆盖 manifest 声明。

## 3. manifest.json 字段速查

| 字段 | 必需 | 默认 | 约束 / 说明 |
|---|---|---|---|
| `id` | ✓ | — | 反域名风格 `^[a-z0-9]+(\.[a-z0-9-]+)+$`，全局唯一；同 id 高版本 = 升级（保留插件数据） |
| `name` | ✓ | — | ≤ 8 个汉字宽度 |
| `version` | ✓ | — | semver；升级必须更大（内置插件改了 assets 不升版本不会生效） |
| `apiVersion` | ✓ | — | 当前为 1；要求 > 宿主提供值时拒绝启用 |
| `description` / `author` | | 空 | 管理页展示 |
| `entry.ui` | ✓ | — | 面板页文件名 |
| `entry.service` | hooks 非空时✓ | — | 后台脚本文件名 |
| `panel.size` | | 0.6 | 面板占屏比例 0.3~1.0 |
| `panel.topbar` | | true | false = 不占顶栏直显位（见 §2） |
| `gesture` | | 无 | `{edge, type:"swipe", range:[a,b], threshold}`；v1 仅 top；区间长度 ≥ 0.2，top[0,0.25] 为宿主保留区 |
| `settingsCard` | | 无 | 设置卡片 html 文件名 |
| `permissions[]` | | 空 | 见 §7；未声明的桥接口在 `window.gguf` 上**不存在** |
| `hooks[]` | | 空 | 见 §5；每个钩子要求对应权限，缺了拒绝导入 |
| `middleware.scope` | | `["local"]` | 钩子生效来源默认值；含 `"external"` 需 `chat:external` 权限。管线内外只有一条，同一插件天然可服务两侧 |
| `middleware.configurable` | | false | true = 管理页向用户暴露「生效范围」三选一（仅对内/内外通用/仅对外），用户选择覆盖 scope；需 `chat:external` |
| `tools[]` | | 空 | 模型主动调用的工具；需 `chat:annotate`；工具名须以插件短名为前缀 |
| `messageActions[]` | | 空 | 消息角标；需 hooks 声明 `messageAction`；`{id, label, icon?, roles?}`——id 须以插件短名为前缀，label ≤ 6 字符（建议 2 字），icon 省略复用 icon.png，roles 默认 `["assistant"]` |
| `provides[]` | | 空 | 接管宿主能力点（补丁式依赖，v1 仅 `"tts"`）；需对应权限（tts → `cap:tts`）与 `entry.service`，见 §5 的 tts 提供者钩子 |
| `systemClause` | | 空 | 追加进系统提示词的静态条款，≤ 400 字符；需 `chat:context` |

导入时全部校验，任一失败给出中文原因并拒绝安装。未知字段一律忽略（向前兼容）。

## 4. 生命周期与运行环境

```
导入 zip ──校验──► 已安装（默认禁用）
启用 ──权限确认──► 注册手势/图标；有 hooks 则创建隐藏 service WebView（收到 'enable' 事件）
面板首次唤出 ──► 懒创建面板 WebView（保状态；'show'/'hide' 事件）
禁用 ──► 销毁全部 WebView（'disable' 事件）；插件私有存储保留
卸载 ──► 删目录 + 私有存储（用户弹窗确认）
```

- **三个 WebView，一套桥**：service.js（隐藏后台）/ ui.html（面板）/ settingsCard
  （设置卡片）各自独立创建，都注入同一个 `window.gguf`。互通用
  `gguf.events.broadcast(name, payload)`（UI ↔ service 双向）或 `gguf.storage`。
- **运行环境**：插件目录经虚拟域名 `https://plugin.gguf/<id>/` 服务，同目录相对
  引用正常；跨插件目录不可访问；file:// 与摄像头/麦克风/定位一律禁用。
  网络默认**全部拦截**：声明 `net:lan` 放行局域网，`net:internet` 放行公网。
- **主题适配**：宿主注入 CSS 变量 `--gg-bg/--gg-fg/--gg-card/--gg-accent/--gg-muted/--gg-line`，
  用它们配色即自动适配深浅色。
- **图标**：96×96 PNG，推荐「填充圆角方形 + 镂空图形」白色 alpha 蒙版构图
  （宿主按主题 tint；参考内置插件）。

## 5. 钩子速查（service.js）

用 `gguf.hooks.<名字>(async fn)` 注册。**网关钩子**跑在每次请求的管线上（本机聊天
与局域网客户端一视同仁，按 `middleware.scope` 过滤）；**UI 钩子**由聊天界面直接
派发，与网关无关——只声明 UI 钩子的插件完全不影响请求路径性能。

| 钩子 | 类型 | 权限 | 时机 | 预算 | 入参 → 出参 |
|---|---|---|---|---|---|
| `route` | 网关 | `chat:route` | 转发前，串行 | 全体 150ms | turn → `{takeOver?}`；true 即接管本轮（禁止在此调 LLM） |
| `handle` | 网关 | `chat:route` | 接管后 | 120s | (turn, ctl)；`ctl.status(文案)` 报进度、`ctl.finish({content}|{notice})` 结束 |
| `context` | 网关 | `chat:context` | 转发前，并行 | 全体 250ms | turn → `{head?, tail?}`；head 须逐轮字节稳定（KV 缓存），tail 空串 = 零注入 |
| `params` | 网关 | `chat:params` | messages 组装完之后 | 20s | payload → `{params}`；白名单采样键合并；外部客户端显式设过的键不可覆盖 |
| `afterReply` | 网关 | `chat:annotate` | 流式结束后，异步 | 10s | msg → `{content?, notice?}`（流式回合 content 无效） |
| `tool` | 网关 | `chat:annotate` | 模型输出 `<tool>` 标记，流后执行 | 10s | (name, input, turn) → `{notice?, card?}`；card = `{file?, data?}` 追加一条自绘消息卡片（需 `chat:card`） |
| `messageAction` | **UI** | `chat:action` | 用户点消息角标 | 10s | `{actionId, sessionId, message:{id,role,content,reasoning,ts}}` → 返回值忽略，反馈自己给（tts/toast/角标） |
| `tts` | **能力提供者** | `cap:tts` + `provides:["tts"]` | 任何人调 gguf.tts.* | 5s | `{action:'speak'|'stop'|'status', from, text?, pitch?, rate?}`；status 须返回 `{ready,speaking}`。钩子内再调 gguf.tts.* = **调穿**到系统默认实现（可带 pitch/rate 变调）——加工完交回原流程，无回环；超时/熔断自动落回默认 |

turn 统一为 `{ source: "local"|"external", sessionId, text, messages }`。

**能力提供者（补丁式依赖）**：插件间不做"A 依赖 B"的依赖图，只做"补丁"——宿主
流程的具名能力点（发声）自带默认实现，声明 `provides` 即接管；调用方依赖的是
能力点而非某个插件，你被禁用/熔断时一切自动恢复默认。参考内置「猫嗓」插件
（com.gguf.meow）：8 行核心代码实现全局变声。

**判定类请求红线**：任何用 `json_schema` 受限解码做判断/抽取的内部 LLM 调用，
**禁止**带 `repeat_penalty > 1`（实测会把枚举判定系统性打偏）；带 json_schema 且
未指定温度时桥自动用 temperature 0。

## 6. window.gguf API 速查

所有方法返回 Promise；跨桥载荷 ≤ 1MB。

```
gguf.version / gguf.plugin / gguf.host        // 环境快照；gguf.host.models() 列可用 GGUF

gguf.llm.chat({messages, temperature?, top_p?, max_tokens?, json_schema?})   // llm 权限
gguf.llm.chatStream(opts, onDelta)
gguf.llm.classify({messages, question, labels})   // 前缀扩展式单选判定（与回答共用 KV）
gguf.memllm.ensure/chat/status/unload             // 第二模型实例（重型记忆用），llm 权限

gguf.chat.current() / gguf.chat.messages({limit?})        // chat:read
gguf.sessions.list() / gguf.sessions.load(id)             // sessions:read

gguf.storage.get/set/remove/keys      // 插件私有 KV，总量 ≤ 5MB，无需权限
gguf.events.on('show'|'hide'|'enable'|'disable'|自定义, fn)
gguf.events.broadcast(name, payload)  // 同插件 UI ↔ service 互通

gguf.ui.close() / gguf.ui.setBadge(n) / gguf.ui.toast(text)   // 无需权限
gguf.tts.speak(text) / gguf.tts.stop() / gguf.tts.status()    // 系统语音，无需权限
gguf.tts.synthesize(text)             // 合成 WAV 不出声 → {url}（变声/RVC 取料口）
gguf.net.fetchAudio({url, json?})     // net:lan/internet：宿主代取音频（插件页面直接
                                      // fetch 自建服务器会撞 CORS——页面源是 plugin.gguf）
gguf.card.post({file?, data?})        // chat:card：往当前会话插一条自绘卡片消息
```

注意：WebView 里**没有** `speechSynthesis`——发声必须走 `gguf.tts`（宿主原生
TextToSpeech；speak 后点顶掉先点）。

## 7. 权限速查

| 权限 | 解锁 | 风险 |
|---|---|---|
| `llm` | `gguf.llm.*` / `gguf.memllm.*` | 低 |
| `chat:read` | 读当前会话消息 | 中（隐私） |
| `sessions:read` | 读全部历史会话 | 高 |
| `chat:context` | context 钩子 + systemClause | 中 |
| `chat:route` | route/handle 钩子（可接管回合） | 高 |
| `chat:annotate` | afterReply 钩子 + tools | 中 |
| `chat:action` | messageAction 钩子 + messageActions 角标 | 中（单条消息） |
| `chat:card` | 消息卡片：tool 返回 card / gguf.card.post | 中 |
| `chat:params` | params 钩子 | 中 |
| `chat:external` | scope 可含 external（影响对外 API） | 高 |
| `net:lan` / `net:internet` | fetch 局域网 / 公网 | 中 / 高 |

`storage`、`ui.*`、`tts.*` 始终可用，不需声明。原则：**能不要的权限就别声明**——
权限清单会在用户启用时展示，要得越多用户越犹豫。

## 8. 稳定性规则（宿主强制，写代码前先读）

1. **预算硬执行**：每个钩子超预算即视为「本轮无返回」，宿主绝不等待。
2. **熔断**：同一插件连续 3 次超时/异常 → 全部钩子自动旁路 + 顶栏红点，
   用户可在管理页看到错误详情（含 JS 异常信息）并一键恢复。
3. **fail-open**：插件管线任何异常都不阻断请求——你的插件坏了，最坏效果等于
   「像没装一样」，但绝不能拖慢或搞挂对话。写钩子时按这个心智设计：能 return {}
   就别 throw。
4. **KV 缓存纪律**：`context.head` 必须逐轮字节稳定（变一次 = 整窗重预填充，
   手机上以分钟计）；检索类动态内容放 `tail`；`head+tail` 每插件 ≤ 上下文 1/8。
5. 流式期间不分发任何钩子；`afterReply`/`tool` 都在流结束后异步执行。

## 9. 调试

- **管理页错误列表**：熔断红点 → 展开插件行，看最近 20 条错误（含钩子名与异常）。
- **日志记录模式**：设置 → 日志 → 开启后宿主把服务/网关/插件调用落盘，可导出。
- **logcat**：网关标签 `GGUF-gw`（context 注入长度、工具标记扫描等）。
- **自查口诀**：「插件像没装一样」= 多半是钩子超时被旁路或 fail-open 兜住了，
  先看管理页错误，再开日志记录模式复现。
- service.js 里 `console.log` 可在 `adb logcat` 的 WebView console 输出里看到
  （tag `chromium`）。

## 10. 完整示例：朗读插件（角标 + 工具 + 语音消息卡片）

内置 `com.gguf.tts` 就是为示范这些路径写的，全文见
`android/app/src/main/assets/plugins/com.gguf.tts/`。要点：

```json
{
  "id": "com.gguf.tts", "name": "朗读", "version": "1.1.0", "apiVersion": 1,
  "entry": { "ui": "ui.html", "service": "service.js" },
  "panel": { "size": 0.4, "topbar": false },
  "permissions": ["chat:action", "chat:annotate", "chat:card"],
  "hooks": ["messageAction"],
  "tools": [{ "name": "tts.say", "description": "把一句话变成语音消息…", "input": "text" }],
  "messageActions": [{ "id": "tts.speak", "label": "朗读", "roles": ["assistant", "user"] }]
}
```

```js
// service.js 核心一：角标——点一下读、再点同一条停、点另一条切换
var lastMsgId = null;
gguf.hooks.messageAction(async function (a) {
  var text = toSpeakable(a.message.content);      // 清洗 Markdown 记号
  if (!text) return {};
  var st = await gguf.tts.status().catch(function () { return null; });
  if (st && st.speaking && lastMsgId === a.message.id) {
    lastMsgId = null; await gguf.tts.stop(); return {};
  }
  lastMsgId = a.message.id;
  await gguf.tts.speak(text);
  return {};
});

// service.js 核心二：模型调用 tts.say 工具 → 返回 card → 对话里出现语音消息气泡
gguf.hooks.tool(async function (name, input) {
  if (name !== 'tts.say') return {};
  return { card: { file: 'card.html', data: { text: String(input), postedAt: Date.now() } } };
});
```

```js
// card.html 核心：交互就是标准 DOM 事件——点按播放/停止、长按展开文字、
// 自动播放靠 data.postedAt 判"新鲜"（滚动重建的旧卡片不会突然出声）
bubble.addEventListener('click', function () { mine ? stop() : play(); });
bubble.addEventListener('touchstart', startLongPressTimer);   // 450ms → 展开文字
var fresh = data.postedAt && (Date.now() - data.postedAt) < 20000;
if (fresh) gguf.storage.get('autoplay').then(function (v) { if (v !== false) play(); });
```

## 11. 发布前检查清单

- [ ] `id` 反域名、`version` 比旧版大、`apiVersion` = 1
- [ ] 权限最小化；hooks 与权限一一对应（导入器会校验，但先自查）
- [ ] icon.png 96×96 单色 alpha 蒙版，深浅色下都可读
- [ ] 面板 CSS 用 `--gg-*` 变量；**不要** `html,body{height:100%}` 撑高（面板创建
      时视口高度可能未定），用自然文档流 + `min-height:100%`
- [ ] 所有钩子在预算内返回；不确定的路径 try/catch 后 return {}
- [ ] `context.head` 字节稳定；动态内容在 `tail`
- [ ] messageActions 的 label ≤ 2 字为佳；每插件角标 ≤ 2 个
- [ ] 纯角标/纯后台插件声明 `panel.topbar: false`
- [ ] 消息卡片：`data.text` 必填（上下文/降级靠它）；页面无状态可重建；
      自动副作用（发声等）用 data 时间戳判新鲜，滚动重建不得重放；卡片自身不滚动
- [ ] zip 内无绝对路径/`..`/符号链接；总大小 ≤ 20MB
- [ ] 真机过一遍：启用 → 权限弹窗 → 各露出面出现 → 禁用 → 数据保留 → 再启用
