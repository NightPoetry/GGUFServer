# GGUF 工具插件规范（v1 草案）

> 状态：v1 已实现并在真机验证（App ≥ 1.0.1），桥接口 `apiVersion = 1`。
> 实现相对本规范的已知偏差：§4.4 的 v1 实现口径（仅 top 边缘、门户选项卡制）；
> afterReply 对流式回合仅限旁路副作用（§6.9 notice 时机条目是精确定义）。

## 0. 背景与目标

当前便签、回忆检索等能力硬编码在 `ChatViewModel` 的发送路径上：每次 `send()` 都要先跑
意图正则路由，命中便签意图时还要发起 1~2 次**非流式** LLM 调用（思考 + 受限解码执行），
系统提示词里也常驻便签协议条款。结果是主对话链路被拖慢、回复不再是纯流式。

本规范把这类「非核心、可拆卸」的能力全部抽成**工具插件**，目标：

1. **零插件 = 裸流式**：没有启用任何带钩子的插件时，发送路径与纯流式对话完全一致——
   没有正则路由、没有额外 LLM 调用、没有提示词附加条款。这是硬性保证，不是优化目标。
2. **默认关闭**：所有插件（含内置的便签、记忆）安装后默认禁用，用户手动启用。
3. **同一规范**：内置插件与用户上传的自定义插件走完全相同的格式、接口和限制，
   内置插件即规范的参考实现（dogfooding）。
4. **HTML 技术栈**：插件界面和执行逻辑都用 Web 技术编写，复用宿主已有的 WebView
   基础设施（现「交互门户 → 浏览器」选项卡），无需插件作者懂 Android。
5. **插件即中间件**：插件不只服务本机聊天界面——外部客户端调用手机的 OpenAI 兼容
   API 时，同样经过启用插件的钩子管线（记忆注入、便签工具等）。一个插件可以同时
   具有 UI 形态和中间件形态。

## 1. 概念模型

### 1.1 一个插件，三种形态

同一个插件可以同时具有三种面向，各自独立、可任选组合：

| 形态 | 面向谁 | 载体 | 例子（记忆插件） |
|---|---|---|---|
| **UI** | 人直接用 | `ui.html`，手势/图标唤出面板 | 浏览、编辑记忆条目 |
| **中间件** | 每一次经过网关的请求自动生效 | `service.js` 的 route/context/afterReply 钩子 | 对请求做关键字检索、把相关记忆注入提示词 |
| **工具** | 模型在回复中主动调用 | `manifest » tools` + 流内标签协议 | 模型说「我帮你记住了」并写入一条记忆 |

中间件不是「给 AI 调的工具」——它是请求管线上的处理器：提示词注入、关键字查找、
上下文改写、请求拦截都发生在这里，无论请求来自本机聊天界面还是局域网上的外部
客户端（这正是把钩子放进网关而不是聊天界面的原因，见 §6.8）。工具调用只是让模型
也能主动触发插件能力的一条窄通道（§6.9）；UI 则让人不经过模型直接操作同一份数据。

### 1.2 插件包的构成

一个插件由五部分构成：

| 构成 | 载体 | 用途 |
|---|---|---|
| 清单 | `manifest.json` | 身份、版本、权限、钩子声明 |
| 图标 | `icon.png` | 顶栏插件按钮、插件管理页 |
| 手势 | `manifest.json » gesture` | 从屏幕某条边滑出插件面板 |
| 界面代码 | `ui.html`（及其引用的本地资源） | 插件的可见界面，跑在面板 WebView 里 |
| 执行代码 | `service.js`（可选） | 后台钩子逻辑，跑在隐藏 WebView 里 |

宿主提供四样东西：

- **请求网关**：常驻公开端口的轻量 HTTP 代理（现 ImageProxy 的泛化）。本机聊天与
  外部客户端的请求都从这里过，插件钩子在网关内执行——中间件因此对两种来源一视同仁。
- **面板容器**：现「交互门户」泛化为通用插件面板，按手势边缘决定呈现形态
  （顶部下拉面板 / 底部上拉面板 / 左右侧滑面板）。
- **JS 桥 `window.gguf`**：插件访问本机模型、会话、存储的唯一通道，按权限裁剪。
- **钩子总线**：把请求生命周期事件（路由、注入、回复后）分发给启用了对应钩子的
  插件，并强制执行时间预算与熔断。

## 2. 插件包格式

插件是一个 zip 包（后缀 `.zip` 或 `.gtool`，按内容识别），解压后即插件目录：

```
notes-plugin.zip
├── manifest.json        # 必需
├── icon.png             # 必需，96×96
├── ui.html              # 必需（纯后台插件可为一个说明页）
├── service.js           # 可选，声明了 hooks 时必需
└── assets/…             # 可选，ui.html 引用的本地 css/js/图片
```

限制：包内文件总大小 ≤ 20 MB；不允许符号链接；路径不允许 `..`。

### 2.1 manifest.json 字段

```jsonc
{
  "id": "com.gguf.notes",          // 必需。反域名风格，全局唯一，装同 id 视为升级
  "name": "便签",                   // 必需。≤ 8 个汉字宽度，用于按钮长按提示与管理页
  "version": "1.0.0",              // 必需。semver，升级时新版本必须更大
  "apiVersion": 1,                 // 必需。要求的宿主桥接口版本，不匹配则拒绝启用
  "description": "会话便签，支持模型协议写入", // 可选
  "author": "gguf",                // 可选
  "entry": {
    "ui": "ui.html",               // 必需
    "service": "service.js"        // 可选。声明 hooks 时必需
  },
  "gesture": {                     // 可选。省略则只能通过顶栏图标唤出
    "edge": "top",                 // top | bottom | left | right
    "type": "swipe",               // v1 仅 swipe，字段预留扩展（如 edge-longpress）
    "range": [0.0, 0.5],           // 沿该边缘的起止比例，见 §4
    "threshold": 48                // 可选。触发位移（dp），默认 48
  },
  "panel": {                       // 可选。面板呈现参数
    "size": 0.6,                   // 面板占屏比例（0.3~1.0），默认 0.6
    "topbar": true                 // 是否占顶栏直显图标位，默认 true。纯角标/纯后台插件
                                   // 建议 false——启动台/门户选项卡/手势照常可达（§3）
  },
  "permissions": [                 // 可选。见 §7，未声明的桥接口直接不可见
    "llm", "chat:read", "chat:context", "chat:route", "chat:annotate"
  ],
  "hooks": [                       // 可选。见 §6，声明才会被分发
    "route", "context", "afterReply"
  ],
  "middleware": {                  // 可选。钩子的生效范围，省略 = ["local"]
    "scope": ["local", "external"],// local = 本机聊天界面；external = 局域网客户端（作者默认值）
    "configurable": true           // 可选。true = 管理页向用户暴露「生效范围」三选一
                                   // （仅对内/内外通用/仅对外），用户选择覆盖 scope；需 chat:external
  },
  "tools": [                       // 可选。教模型主动调用的工具，见 §6.9
    {
      "name": "notes.append",      // 必须以插件短名为前缀，匹配 ^[a-z0-9.-]+$
      "description": "把一条要点追加进用户便签",
      "input": "text"              // text = 标签体为纯文本；json = JSON 对象
    }
  ],
  "provides": ["tts"],             // 可选。接管宿主能力点（补丁式依赖），见 §6.13
  "messageActions": [              // 可选。消息下方动作行里的角标按钮，见 §6.11
    {
      "id": "tts.speak",           // 必须以插件短名为前缀，匹配 ^[a-z0-9.-]+$
      "label": "朗读",              // 角标文字，≤ 6 字符（与「复制」同排，宜 2 字）
      "icon": "speak.png",         // 可选。专属图标（96×96 alpha 蒙版）；省略用插件 icon.png
      "roles": ["assistant"]       // 可选。出现在哪些消息下：assistant / user，默认仅 assistant
    }
  ],
  "systemClause": "你可以写本会话的便签：……"  // 可选。追加进系统提示词的条款，见 §6.5
}
```

校验规则（导入时执行，任一失败即拒绝导入并给出原因）：

- JSON 可解析、必需字段齐全、`id` 匹配 `^[a-z0-9]+(\.[a-z0-9-]+)+$`；
- `entry` 指向的文件存在；`hooks` 非空时 `entry.service` 必须存在；
- `hooks` 里出现的钩子必须有对应权限（如 `route` 钩子要求 `chat:route` 权限）；
- `middleware.scope` 含 `external` 时要求 `chat:external` 权限；
- `tools` 非空时要求 `chat:annotate` 权限（执行走 afterReply 通道），
  工具名必须以插件短名（id 最后一段）为前缀；
- `messageActions` 非空时要求 `hooks` 声明 `messageAction`（连带要求 `chat:action`
  权限与 `entry.service`）；角标 id 必须以插件短名为前缀，`label` ≤ 6 字符，
  `icon` 指向的文件必须存在；
- `systemClause` ≤ 400 字符，且要求 `chat:context` 权限。

## 3. 图标规范

- 文件：`icon.png`，96×96 像素，透明背景。
- 推荐做成**单色 alpha 蒙版**（白色图形 + 透明背景）：宿主按当前主题着色，
  深浅色模式自动适配。非单色图标原样显示，不保证暗色下可读。
- 展示位置：
  - **顶栏插件区**：已启用且 `panel.topbar ≠ false` 的插件在顶栏获得一个图标按钮，
    点按唤出/收起面板。直显数量按屏宽自适应，超出的收进启动台（顺序可在管理页拖动调整）。
    `panel.topbar: false` 的插件（纯角标/纯后台形态）不占直显位。
  - **启动台**：顶栏「启动台」下拉的方格面板，恒列出**全部**已启用插件（含 topbar:false
    的）——它是面板唤出的永远兜底入口，任何插件都不会因配置而失去入口。
  - **插件管理页**：图标 + 名称 + 版本 + 启用开关 + 权限列表。
  - **消息角标**（§6.11）：声明了 `messageActions` 的插件，在消息下方动作行
    （复制/重试那排）以 13dp 小图标 + 短文字出现；默认复用 `icon.png`，
    也可在动作里用 `icon` 字段指定专属图标（同样是单色 alpha 蒙版）。
- 插件可通过 `gguf.ui.setBadge(n)` 在自己图标上显示数字角标（0 清除）。

## 4. 手势规范

### 4.1 声明方式

手势用「边缘 + 区间 + 类型」描述：

- `edge`：从哪条屏幕边缘滑入。`top` / `bottom` / `left` / `right`。
- `range`：`[start, end]`，0~1，表示沿这条边的起止比例。
  `top`/`bottom` 沿 x 轴（0 = 左端），`left`/`right` 沿 y 轴（0 = 顶端）。
  例：`{"edge":"top","range":[0.5,1.0]}` = 从顶部右半区下滑唤出。
- `type`：v1 只有 `swipe`（沿边缘法线方向滑动超过 `threshold` dp 触发）。

### 4.2 宿主预留区（插件不可申领）

| 区域 | 归属 |
|---|---|
| `left  [0,1]` | 历史会话抽屉（现状保留） |
| `right [0,1]` | 模型配置抽屉（现状保留） |
| `top [0,0.25]` | 宿主保留（状态灯/系统区） |

即 v1 里插件实际可申领：`top [0.25,1]` 与 `bottom [0,1]` 的任意子区间。
区间长度不得小于 0.2（太窄划不准）。

### 4.3 冲突解决

- 申领区间与预留区或**已启用**插件的区间重叠 → 启用时弹窗提示冲突，
  该插件以「无手势」状态启用（图标唤出仍可用），用户可到管理页手动改区间
  （用户改过的区间持久化，覆盖 manifest 声明）。
- **图标按钮永远是兜底唤出方式**——手势只是快捷方式，没有手势的插件不损失功能。

### 4.4 面板呈现

手势边缘决定面板形态（无手势的插件默认 `top` 形态）：

| edge | 面板形态 |
|---|---|
| `top` | 顶部下拉面板（同现「交互门户」，反向滑动或点击遮罩收起） |
| `bottom` | 底部上拉面板（bottom sheet，v1 预留） |
| `left` / `right` | 侧滑面板，宽 85%（v1 因预留区实际不可申领，字段预留） |

**v1 实现口径**：宿主只实现 `top` 边缘。交互门户即顶部面板容器——每个启用的
插件是其中一个选项卡（内置「浏览器」恒为最后一个选项卡）；`range` 的语义是
「从顶部这段横向区域下拉时，面板直接定位到本插件的选项卡」，未被申领的区域
下拉则打开上次停留的选项卡。区间重叠冲突（§4.3）与图标兜底照旧适用。
bottom/left/right 是预留字段，声明了也按无手势处理。

面板内是全屏 WebView 加载插件 `ui.html`。同一时刻只有一个插件面板打开；
打开另一个会先收起当前的。系统返回键优先收面板。

## 5. 界面运行环境（ui.html）

- WebView 配置：启用 JavaScript 与 DOM Storage；**禁用**文件系统访问
  （`file://`）、地理位置、摄像头/麦克风。
- 插件目录经虚拟域名映射提供服务：`https://plugin.gguf/<id>/ui.html`。
  同目录相对引用（`./assets/x.css`）正常工作。跨插件目录不可访问。
- 网络：默认**全部拦截**（本地模型调用请走 `gguf.llm`）。声明 `net:lan` 放行局域网/
  127.0.0.1，声明 `net:internet` 放行公网（启用时红字提示用户）。
- 主题：宿主注入 CSS 变量到 `:root` —— `--gg-bg` `--gg-fg` `--gg-card` `--gg-accent`
  `--gg-muted`，并保证 `prefers-color-scheme` 正确反映系统深浅色。
- 生命周期：面板 WebView **懒创建**（首次唤出时），收起面板时保留实例（保状态），
  插件被禁用或内存吃紧时销毁。事件：`gguf.events.on('show'|'hide')`。
- 宿主在加载插件代码前注入 `gguf-sdk.js`，提供 `window.gguf`（见 §8）。

## 6. 执行代码与钩子（service.js）

`service.js` 跑在一个**隐藏 WebView**（无界面，同样注入 `gguf`）里，
仅当插件「已启用」且声明了 `hooks` 时才创建，禁用即销毁。
它是插件的常驻逻辑：注册钩子、响应对话事件。UI 面板与 service 之间用
`gguf.storage` 或 `gguf.events.broadcast()`（插件内部广播）通信。

### 6.1 钩子总线时序

钩子**在网关内执行**（§6.8），对本机聊天与外部客户端一视同仁（按 scope 过滤）：

```
POST /v1/chat/completions 到达网关（来源：本机聊天 或 外部客户端）
  │
  ├─(有 scope 匹配且启用 route 钩子的插件?)──否────► 直接转发上游，流式透传  ← 零插件快路径
  │           是
  ▼
  route 钩子（串行，按管理页顺序；总预算 150ms）
  │   某插件返回 takeOver:true ──► 该插件接管本轮（§6.3），请求不再转发上游
  ▼
  context 钩子（并行；总预算 250ms）──► 注入块写进请求 messages
  ▼
  params 钩子（串行；总预算 20s，仅有插件声明时存在，§6.10）──► 采样参数按白名单合并进请求体
  │                                                              ──► 转发上游（照常流式！）
  ▼  SSE 透传中：仅做工具标记扫描（§6.9），其余字节即到即转
  ▼  流式结束（[DONE]）
  afterReply 钩子 + 工具执行（异步，不阻塞任何连接；单插件预算 10s）
```

**红线**：`route`、`context` 与 `params` 是请求路径上仅有的同步点，预算耗尽立即跳过
（该插件本轮视为无返回），转发绝不等待任何插件超过预算之外的时间。`params` 的大预算
只在「插件主动选择 LLM 判断路径」时才可能被吃到（见 §6.10 的 KV 共用论证——判断预填的
是回答本来要付的前缀）；未启用任何 params 插件时该同步点不存在。

### 6.2 route —— 意图路由（权限 `chat:route`）

```js
gguf.hooks.route(async (turn) => {
  // turn = { text, noteContext: {...插件自存的轻量状态} }
  if (/帮我记一下/.test(turn.text)) return { takeOver: true };
  return {};   // 不接管
});
```

- 只做**快速判定**（正则/关键词级别），预算内必须返回。禁止在 route 里调 LLM。
- 返回 `{ takeOver: true }` 的第一个插件获得本轮控制权，后续插件不再询问。

### 6.3 接管回合（takeOver）

接管后宿主插入一条占位助手消息并回调插件的 `gguf.hooks.handle`：

```js
gguf.hooks.handle(async (turn, ctl) => {
  ctl.status("正在整理便签…");                    // 占位消息上的进度文案
  const out = await gguf.llm.chat({ messages: [...], json_schema: {...} });
  // …执行动作…
  ctl.finish({ notice: "已记入便签：周五交房租" });  // 或 { content: "正文回复" }
});
```

- 接管总预算 120 秒；用户点停止 = `ctl` 收到中止信号，插件应尽快退出，
  宿主无论如何在中止后强制结束回合。
- `finish({notice})` 渲染为现有的「📌 图标确认条」样式；`finish({content})` 渲染为正文。

### 6.4 context —— 上下文注入（权限 `chat:context`）

```js
gguf.hooks.context(async (turn) => ({
  head: "本会话便签（按条编号）：\n1. 周五交房租",   // 拼进首条 system，要求字节稳定
  tail: "更早对话相关片段：…",                      // 注到末条用户消息前，可每轮不同
}));
```

两个槽位对应两种 KV 缓存代价（沿用现实现的经验）：

- `head`：进入首条 system 消息。**要求逐轮字节稳定**——内容变化会使前缀缓存
  整体失效，触发整窗重预填充（4096 上下文的手机上以分钟计）。宿主对比上一轮，
  变化时在日志计数；频繁变化（>1 次/5 轮）在管理页黄字警告该插件。
- `tail`：注到最后一条用户消息之前，作为 system 背景块。允许每轮不同，
  空字符串 = 本轮零注入（走完整缓存快路径）。检索类内容放这里。

多插件的同槽位内容按管理页顺序拼接。`head`+`tail` 每插件合计 ≤ 上下文的 1/8（token 估算）。

### 6.5 systemClause —— 系统提示词条款

manifest 里的静态文本，插件启用时追加到内置系统提示词末尾（用户自定义提示词
整体覆盖时同样追加在其后）。用于教模型协议（如便签的 `<note>` 标记）。
启用/禁用插件才变化 → 只在开关时刻付一次缓存重建代价。

### 6.6 afterReply —— 回复后处理（权限 `chat:annotate`）

```js
gguf.hooks.afterReply(async (msg) => {
  // msg = { id, content, reasoning }
  const m = msg.content.match(/<note>([\s\S]*?)<\/note>/);
  if (!m) return {};
  return {
    content: msg.content.replace(/<note>[\s\S]*?<\/note>/, "").trim(), // 改写正文
    notice: "已记入便签：" + m[1].trim(),                               // 附加确认条
  };
});
```

异步执行，完全在流式结束之后，不影响下一轮发送。

### 6.7 熔断

- 同一钩子**连续 3 次**超预算或抛异常 → 该插件所有钩子自动旁路（bypass），
  顶栏图标出现红点，管理页显示最近错误（含 JS 异常栈），用户可一键恢复。
- service.js 加载失败/崩溃 → 插件自动降级为「仅 UI」状态并提示。
- **网关整体 fail-open**：插件管线的任何异常（含 service WebView 不可用，如系统
  回收）都不阻断请求转发——最坏情况等于零插件透传，外部 API 永远可用。

### 6.8 网关与中间件

中间件能力（提示词注入、关键字检索、请求拦截等）的落点是**请求网关**：

- **端口拓扑**：公开端口永远由网关监听（现 ImageProxy 泛化而来），llama-server
  固定运行在内部端口（公开端口 + 1）且只绑 127.0.0.1。图片压缩降级为网关的第一个
  内置处理步骤（开关与行为不变）。
- **管线范围**：只有 `POST /v1/chat/completions` 走插件管线；其余端点透明转发。
- **来源与会话**：本机聊天界面的请求带 `X-GGUF-Session: <会话id>` 头，外部请求
  没有。钩子入参统一为
  `turn = { source: "local"|"external", sessionId: string|null, text, messages }`
  （`text` = 最后一条用户消息）。生效范围不含该来源的插件整体跳过。
- **管线内外通用，范围用户可选**：中间件管线只有一条，内外请求走同一套钩子——
  不存在"对内版插件/对外版插件"之分，同一个记忆插件既能服务本机也能服务局域网
  客户端。生效范围的判定值 = **用户在管理页的三选一覆盖 ?: manifest.scope 默认**；
  插件声明 `middleware.configurable: true` 才向用户暴露这个三选一（仅对内 /
  内外通用 / 仅对外——最后者即 onlyoutside：纯对外中间件，本机聊天不受影响）。
  暴露选择器要求 `chat:external` 权限——用户改选"对外"时，权限已在启用时确认过。
- **上下文组装是宿主内置中间件**（非插件）：消息窗口预算裁剪（阶梯式 winStart，
  按会话保持前缀字节稳定 → KV 缓存命中）、跨天消息的时间标注、尾部背景块的注入
  时机，全部从 ChatViewModel 迁入网关，本机与外部客户端统一受益。本机请求的消息
  可带 `gguf_ts` 扩展字段（epoch ms）供时间标注使用——网关消费后**剥除一切
  `gguf_*` 字段**再转发，上游 llama-server 永远看不到扩展字段。
- **接管的响应合成**：takeOver 时网关按请求的 `stream` 参数合成标准 OpenAI 格式
  响应（流式则合成 chunk 序列 + `[DONE]`），外部客户端无感。
- **通知通道**：插件产生的确认条（notice）附着在最后一个 SSE chunk 的顶层
  `"gguf"` 扩展字段：`{"gguf":{"notices":[{"plugin":"com.gguf.notes","text":"已记入便签：…"}]}}`。
  本机客户端渲染成图标确认条；标准 OpenAI SDK 忽略未知字段，外部客户端零影响。
  非流式响应同理附在响应 JSON 顶层。
- **防回环**：插件经 `gguf.llm.*` 发起的模型调用直连内部端口，不再进入插件管线。

### 6.9 工具调用协议（不打断流式）

让模型在回复中主动调用插件能力，同时**绝不牺牲流式输出**——模型必须先输出给用户
看的正文，工具标记只能跟在正文之后；「一声不吭直接调工具」被协议本身排除。

- **声明**：manifest `tools[]`（名称、描述、`input: text|json`）。宿主据此自动生成
  教学条款拼进系统提示词（与 systemClause 同一区域），格式：

  ```
  <tool name="notes.append">周五交房租</tool>
  ```

  教学条款强制要求：先用正文回应用户（说明你做了什么），再在**回复末尾**输出标记；
  没有明确需要时绝不输出标记。
- **流式过滤**：网关边转发边扫描 `<tool` 前缀；从疑似标记起点开始暂扣（上限 4 KB
  或至流结束），确认为完整合法标记 → 吞下不转发；证伪 → 原样补发。标记按协议
  位于末尾，暂扣窗口通常为零。
- **执行时机**：流结束后执行，执行回调：service.js 里
  `gguf.hooks.tool(async (name, input, turn) => ({notice}))`。
- **notice 的在带下发时机**（精确定义，避免拖慢无关回合）：
  - 本轮**吞掉了工具标记** → 网关暂缓转发收尾 chunk 与 `[DONE]`，等工具执行完
    （≤10s）再补发 notice chunk + `[DONE]`。此时正文早已流完，用户看到的只是
    「流结束信号」晚到几秒。
  - 本轮**没有标记** → `[DONE]` 零延迟转发；afterReply 只做旁路副作用。
    对流式响应，afterReply **不能**改写正文（字节已发出）；改写正文仅对
    非流式响应有效（§6.6 的 content 字段在流式回合被忽略）。
- **形态定位**：v1 工具是**旁路副作用型**——执行结果不回喂模型再生成一轮（那会
  打断流式）。需要「模型先拿到数据再回答」的场景，用 context 钩子在发送前注入。
- **原生 tools 透传**：请求自带 OpenAI `tools` 字段时（外部客户端自己的函数调用），
  网关不注入教学条款、不做标记过滤，原样转发——绝不干扰客户端的工具协议。
  插件工具不走原生 `tools` 通道：本栈上 `tool_choice=auto` 依赖模板标记懒触发，
  1B 模型间歇性失败（见《架构与原理》与开发记录），流内标签 + 代码解析才是
  小模型可靠路径。

### 6.10 params —— 按任务自适应采样参数（权限 `chat:params`）

聊天是唯一「任务类型事先未知」的请求路径：写作要高温、代码/计算要近贪心、闲聊要
官方推荐档+DRY 防复读。`params` 钩子让插件在转发前判断本轮任务、返回采样参数档：

```js
gguf.hooks.params(async (payload) => ({
  // payload = { source, sessionId, text, messages(最终组装完), clientParams(客户端已设的键), dropped }
  params: { temperature: 0.7, top_p: 0.95, dry_multiplier: 0.8 },
}));
```

- **白名单合并**（网关执行）：temperature / top_p / top_k / min_p / repeat_penalty /
  presence_penalty / frequency_penalty / dry_* / top_n_sigma / xtc_*。数值型字段才生效。
- **优先级按来源**：`external` 客户端**显式设过的键不可覆盖**（尊重 API 调用者意图，
  只补缺）；`local` 的 body 参数是配置抽屉滑杆的通用缺省 → 插件按任务的判断**覆盖**它
  （配置抽屉在参数导演启用时明示「滑杆仅兜底」）。
- **时机**：在 context/systemClause **之后**——插件若走 LLM 判断，判断请求必须以
  「最终组装完的 messages」为前缀，才能与本次转发共用 KV。
- **LLM 判断路径 `gguf.llm.classify({messages, question, labels})`**（`llm` 权限）：
  **KV 共用铁律——判断请求必须是回答请求同一前缀的严格后缀扩展**。调用方把钩子入参的
  `messages` 原样透传，宿主只在**末尾追加**一条判断 system 消息 + json_schema 顶层
  enum（受限解码 1-2 token）。判断时公共前缀（上文+本轮用户消息）全部命中缓存、只预填
  判断指令几十 token；判断后 llama-server 剪尾（与「重试候选」同机制，纯删 KV 不重算），
  回答请求只补 assistant 开头即流式——判断零缓存残留，还顺手替回答付了本轮用户消息的预填。
- **判定采样红线**：`classify` 固定 temperature 0 + 受限枚举，**绝不带
  repeat_penalty / DRY**——实测惩罚采样会把受限枚举判定系统性打偏（假阴 0→9，
  《推理参数与外部知识架构研究》§三）。同理，任何插件对判定/抽取类内部请求
  （memllm L2、工具轮）都**禁止**设置 `repeat_penalty > 1`。
- **判定保护（宿主内置，不可关）**：管线入口检测**受限解码请求**（`json_schema` /
  `grammar` / `response_format` 指定 JSON）并做两件事：① 中和请求携带的惩罚采样
  （repeat_penalty→1.0、presence/frequency→0，改动记日志）——许多客户端库默认静默
  携带 rp 1.1，对受限判定是上面红线描述的毒药；② **跳过 params 钩子**——判定/抽取类
  请求的参数由调用方定型，聊天三档不适用（绝不让聊天档踩掉调用方特意设的判定温度）。
  DRY 与温度不动（DRY 实测对枚举判定无害；温度是调用方正当选择）。边界：判定保护随
  插件管线生效——「零中间件极速路径」不解析请求体（性能红线），出厂裸流式状态下不生效。
- **桥侧判定档缺省**：`gguf.llm.chat` / `gguf.memllm.chat` 带 `json_schema` 而未指定
  温度时，缺省 temperature 0（封闭式判定贪心最准；显式给温度则尊重）。
- **fail-open**：超时/异常 = 无覆盖 = 现状行为；插件返回的 `params` 永远不改 messages，
  不存在 head 字节稳定性问题。

### 6.11 messageAction —— 消息角标（权限 `chat:action`）

消息下方的动作行（复制 / 速度 / 重试那排）向插件开放：manifest 声明 `messageActions[]`
（见 §2.1），每条动作在符合 `roles` 的消息下渲染成一个「小图标 + 短文字」角标，
与「复制」同一视觉语言。点击时宿主把**该条消息**派发给 service.js：

```js
gguf.hooks.messageAction(async (a) => {
  // a = { actionId, sessionId, message: { id, role, content, reasoning, ts } }
  await gguf.tts.speak(a.message.content);   // 例：朗读插件
  return {};
});
```

- **纯 UI 侧钩子**：由聊天界面直接派发，**不进网关管线**——只声明 `messageAction`
  的插件不算中间件，绝不把网关拖出零插件快路径（§10 红线 1 不受影响）。
  同理它只对本机聊天界面存在，`middleware.scope` 对它无意义。
- **时机与预算**：用户点击时派发，单次预算 10s；返回值被忽略（动作反馈由插件
  自己给：发声、`gguf.ui.toast`、图标数字角标等）。超时/异常计入熔断（§6.7）。
- **展示条件**：插件已启用且未熔断；消息不在流式中且正文非空；`roles` 匹配
  （默认仅 assistant）。流式期间照旧不渲染动作行，与现状一致。
- **典型用途**：TTS 朗读（配 `gguf.tts.*`，见 §8——WebView 无 speechSynthesis，
  发声必须经宿主桥）、翻译、收藏到便签、导出单条消息等「对着一条消息做动作」的能力。
- **克制建议**：动作行宽度有限，每个插件建议至多 1~2 个角标、label 2 个字。

参考实现：内置朗读插件 `com.gguf.tts`（`chat:action` 单权限 + `messageAction`
单钩子 + `gguf.tts`，点一下朗读、再点同一条停止、点另一条切换）。

### 6.12 消息卡片 —— 插件自绘的一条消息（权限 `chat:card`）

对话消息列表向插件开放「一条消息的**正文区域**」：卡片消息不走宿主的 Markdown
渲染，而是**每条卡片一个插件 WebView**，加载插件目录内的卡片页（默认 `card.html`）。
正文区域内的样式、布局、交互全部归插件——这就是"给插件开放一个 div"：

- **边界（硬性）**：插件接管的只有正文渲染容器。头像、动作行（复制/角标）、消息
  间距与布局框架全部是宿主的，与普通消息完全一致——卡片就是一条普通消息，只是
  正文换了渲染器，天然与普通消息在列表里混排，插件不能改动原版框架的任何部分。

- **交互即 DOM**：点击、长按、左右滑、拖动……都是卡片页里的标准 DOM 事件
  （click / touchstart / pointermove / contextmenu…），宿主不发明任何回调协议。
  竖直滚动仍归消息列表（卡片内容应自适应高度、自身不滚动）。
- **数据注入**：宿主在 SDK 之前注入 `window.__ggufCard = { key, data }`，
  `key` 是卡片键（消息 id）、`data` 是产生卡片时传入的 JSON。
- **内部文本约定**：`data.text` 是卡片的等价文本，宿主把它存为消息 `content`——
  进模型上下文、可复制、导出，插件被禁用/卸载时降级显示为普通文字（永不丢内容）。
- **高度自适应**：卡片页 `scrollHeight` 经桥自动回报（与设置卡片同机制），宿主据此
  撑高消息行；内容变化（如长按展开文字）自动跟随。透明页面背景，气泡形状插件自己画。
- **生命周期**：卡片 WebView 随列表滚动懒创建/回收——**不要在页面内存状态**，
  用 `__ggufCard.data` 与 `gguf.storage` 重建；「新鲜性」判断（如自动播放只在
  刚产生时触发）用 data 里携带的时间戳。
- **产生路径**（两条）：
  1. **工具路径**：`gguf.hooks.tool` 返回 `{ card: { file?, data? } }` ——工具是本轮
     回复调用的，卡片就**附在本轮回复的同一条消息上**：模型写了正文则正文照常渲染、
     卡片跟在其后同条混排；模型只输出了工具标签（正文为空）则这条消息就是一张卡片，
     绝不会出现空白消息行 + 卡片另起一行的两行渲染。（经收尾 chunk 的 `gguf.cards`
     扩展字段下发，外部 OpenAI 客户端忽略之，只在本机聊天界面成卡。）
  2. **桥路径**：`gguf.card.post({ file?, data? })`（service/面板均可调）——作为一条
     独立的卡片消息直接插进当前会话，不经模型。
- **典型用途**：语音消息（tts.say 工具 → 气泡卡片自动播放，长按展开文字）、
  图表/计算结果卡、可交互小组件（投票、清单勾选）等。

参考实现：朗读插件 v1.1.0 的 `tts.say` 工具 + `card.html` 语音气泡
（点按播放/停止、长按展开文字、自动播放开关在插件面板设置里）。

### 6.13 能力提供者 —— 插件间的补丁式依赖（manifest `provides`）

插件间的依赖不做通用依赖图（A 必须先装 B），只做一种关系：**既定流程上的补丁**。
宿主流程里有具名的**能力点**，每个能力点自带默认实现；插件可以声明自己**提供**
某能力点，从而接管既定流程中的这一段——所有调用方无感知，依赖的是能力点本身，
不是某个具体插件。

v1 定义的能力点：

| 能力点 | 默认实现 | 提供者钩子 | 所需权限 |
|---|---|---|---|
| `tts`（发声） | 系统 TextToSpeech | `gguf.hooks.tts` | `cap:tts` |

**声明与路由**：

```jsonc
// manifest.json（如变声/专用 TTS 引擎插件）
"provides": ["tts"],
"permissions": ["cap:tts"]
```

```js
// service.js —— 所有 gguf.tts.* 调用（朗读角标、语音卡片……）改道到这里
gguf.hooks.tts(async (p) => {
  // p = { action: 'speak'|'stop'|'status', from: 调用方插件id, text?, pitch?, rate? }
  if (p.action === 'speak') {
    await gguf.tts.speak(变声(p.text), { pitch: 1.4 });  // ← 调穿：见下
    return {};
  }
  if (p.action === 'stop') { await gguf.tts.stop(); return {}; }
  if (p.action === 'status') return await gguf.tts.status();
});
```

**补丁语义（核心规则）**：

- **改道**：存在生效提供者（已启用、未熔断）时，其它插件与宿主对该能力的调用
  全部进提供者的钩子。提供者按管理页顺序取第一个（同能力多个提供者时靠前者生效）。
- **调穿**：提供者**自己**调用该能力 = 直达宿主默认实现——补丁加工完把结果交回
  原流程（相当于中间件的 next() / 继承里的 super()），天然无回环。发声的调穿
  可带 `{ pitch, rate }`（0.5~2.0）做变调。
- **揭补丁**：提供者被禁用、卸载或熔断（超时/异常连续 3 次，钩子预算 5s），
  能力自动落回默认实现——原流程永远完好，坏掉的补丁最多让声音"变回原样"。
- **要求**：`provides` 非空需 `entry.service`（钩子在 service.js 响应；无 hooks 的
  纯提供者插件同样会创建 service WebView）。未知能力名向前兼容忽略。
- **不入网关**：能力提供者是 UI/桥侧机制，不算中间件，不影响零插件快路径。

参考实现：内置「猫嗓」插件 `com.gguf.meow`（provides:["tts"] 单声明——接住全部
朗读、句尾加喵、pitch 1.45 调穿系统引擎；启用即全局变声，禁用即恢复原声，
朗读插件全程无感知）。

## 7. 权限模型

| 权限 | 授予的能力 | 风险提示级别 |
|---|---|---|
| `llm` | `gguf.llm.*`：调用本机 llama-server | 低 |
| `chat:read` | 读当前会话消息、会话元信息 | 中（隐私） |
| `sessions:read` | 读全部历史会话（跨会话记忆用） | 高（隐私，启用时明示） |
| `chat:context` | `context` 钩子 + `systemClause` | 中（可影响模型行为） |
| `chat:route` | `route`/`handle` 钩子，可接管回合 | 高（可拦截对话，启用时明示） |
| `chat:annotate` | `afterReply` 钩子、`tools` 工具执行，可改写回复正文、附确认条 | 中 |
| `chat:action` | `messageAction` 钩子 + `messageActions` 角标：点击时收到该条消息内容 | 中（单条消息隐私） |
| `chat:card` | 消息卡片（§6.12）：工具可返回 card、`gguf.card.post` 可插入插件自绘消息 | 中（可在对话里插内容） |
| `cap:tts` | 提供 `tts` 能力点（§6.13）：接管全机发声，朗读文本流经该插件 | 中（文本流经+行为改变） |
| `chat:params` | `params` 钩子：按任务调整本轮采样参数（external 显式参数不可覆盖） | 中 |
| `chat:external` | 中间件 scope 可含 `external`——影响对外 API 的请求与响应 | 高（启用时明示） |
| `net:lan` | fetch 局域网 / 127.0.0.1 | 中 |
| `net:internet` | fetch 公网 | 高（红字提示：本应用默认离线） |

- `storage`（插件私有 KV）与 `ui.*` 不需要声明，始终可用。
- 权限在**启用时**一次性展示清单，用户确认后生效；manifest 升级新增权限需重新确认。
- 未声明的权限对应的桥接口**不存在**（`undefined`），而非调用时报错。

## 8. JS 桥接口 `window.gguf`（apiVersion 1）

所有方法返回 Promise。跨 WebView 传输为 JSON 序列化，单次载荷 ≤ 1 MB。

```
gguf.version                 // 1
gguf.plugin                  // { id, name, version }（自己的 manifest 摘要）
gguf.host                    // { appVersion, model, contextSize, serverRunning }

gguf.llm.chat(opts)          // 非流式。opts: { messages, temperature?, top_p?,
                             //   max_tokens?, json_schema? } → { content, timings }
gguf.llm.chatStream(opts, onDelta)   // 流式，onDelta(piece)；返回完成 Promise

gguf.chat.current()          // { id, title, tags } | null
gguf.chat.messages(opts)     // 当前会话消息 [{role, content, ts, …}]，opts: {limit?}
gguf.sessions.list()         // [{id, title, updatedAt}]        （需 sessions:read）
gguf.sessions.load(id)       // 完整会话                        （需 sessions:read）

gguf.storage.get(key)        // 插件私有 KV，JSON 值，总量 ≤ 5 MB
gguf.storage.set(key, value)
gguf.storage.remove(key)
gguf.storage.keys()

gguf.hooks.route(fn)         // §6 各钩子注册（service.js 内）。钩子入参 turn 统一为
gguf.hooks.handle(fn)        // { source: "local"|"external", sessionId, text, messages }
gguf.hooks.context(fn)
gguf.hooks.afterReply(fn)
gguf.hooks.tool(fn)          // (name, input, turn) => {notice?, card?}，工具标记的执行回调
                             // card = {file?, data?}：追加一条插件自绘的消息卡片（§6.12，需 chat:card）
gguf.hooks.messageAction(fn) // §6.11 消息角标点击：({actionId, sessionId, message}) => {}

gguf.card.post(opts)         // §6.12 消息卡片（chat:card）：往当前会话插一条自绘卡片消息，
                             // opts = { file?: "card.html", data?: {...} }（data.text = 内部文本）

gguf.tts.speak(text, opts?)  // 发声（能力点 §6.13：有提供者时改道进它；提供者自己调=调穿默认
                             // 系统 TTS，opts 可带 {pitch, rate} 0.5~2.0 变调）。WebView 无 speechSynthesis
gguf.tts.stop()              // 立即静音。speak 后点顶掉先点（QUEUE_FLUSH）
gguf.tts.status()            // { ready, speaking }。tts 与 ui.* 一样不需声明权限
gguf.tts.synthesize(text)    // 合成 WAV 不出声 → { url }（本插件域名下）。变声/RVC 提供者的
                             // 取料口：fetch → Web Audio 解码 → 二次处理 → 自行播放。
                             // OEM 引擎普遍忽略 pitch 参数，改音色只有音频级处理可靠
gguf.tts.synthesizeLocal(o)  // 端侧神经 TTS（sherpa-onnx VITS 二进制，完全离线）：
                             // { text, sid?, speed?, model? } → { url }。模型放 filesDir/tts-models/<名>/
gguf.tts.localStatus()       // { available, binReady, models }：本机神经推理可用性
gguf.hooks.tts(fn)           // §6.13 发声提供者钩子（manifest provides:["tts"] 后被分发）

gguf.net.fetchAudio(opts)    // 宿主代取网络音频（需 net:lan / net:internet）：插件页面直接
                             // fetch 自建服务器会撞 CORS（页面源 https://plugin.gguf，推理服务器
                             // 普遍不回 CORS 头）；宿主原生 HTTP 取回、落插件网络缓存，返回
                             // { status, url, bytes }——url 在本插件域名 __net__/ 下，同源可 fetch。
                             // opts: { url, json?（有则 POST）, method?, timeoutMs? }，响应 ≤ 20MB

gguf.events.on(name, fn)     // 'show' | 'hide' | 'enable' | 'disable' | 广播
gguf.events.broadcast(name, payload)   // 同插件 UI ↔ service 互通

gguf.ui.close()              // 收起自己的面板
gguf.ui.setBadge(n)          // 顶栏图标角标，0 清除
gguf.ui.toast(text)          // 宿主样式的轻提示
```

> 传输协议（实现细节，插件作者无需关心）：宿主调用
> `window.__ggufDispatch(callId, name, payloadJson)`，SDK 把注册的钩子包装成
> Promise 并以 `__ggufHost.respond(callId, resultJson)` 回传；预算计时在宿主侧。

## 9. 安装、启用、卸载

- **安装**：设置 → 插件管理 → 「导入插件」，走 SAF 文件选择器选 zip
  （与模型导入同一交互模式）。校验（§2.1）通过后解压到
  `filesDir/plugins/<id>/`。同 id 且版本更高 = 覆盖升级（KV 存储保留），
  版本相同或更低 = 提示后可强制覆盖。
- **内置插件**：随 APK 以 assets 形式携带，首启时释放到同一目录，
  与导入的插件在管理页无差别展示，同样默认禁用。
- **启用**：展示权限清单 → 用户确认 → 注册手势与顶栏图标 → 若声明 hooks
  则创建 service WebView。
- **禁用**：注销手势/图标/钩子，销毁两个 WebView。KV 存储保留。
- **卸载**：删除插件目录 + KV 存储（弹窗确认，提示数据将清除）。

## 10. 性能与稳定性红线（汇总）

1. 零启用插件（或启用的插件都无 hooks）时，`send()` 不产生任何插件相关开销
   ——不查表以外的逻辑一概没有。
2. `route` 总预算 150 ms、`context` 总预算 250 ms、接管 120 s、`afterReply` 10 s。
3. 流式回复期间不分发任何钩子；`afterReply` 在流式完全结束后异步执行。
4. 连续 3 次超时/异常 → 自动旁路 + 红点。
5. `head` 注入块要求字节稳定；`tail` 为空即零注入。宿主监控并警告违反者。
6. 面板/service WebView 懒创建；禁用即销毁；宿主内存回调（onTrimMemory）时
   优先销毁收起状态的面板 WebView。
7. SSE 透传期间网关只做工具标记扫描，暂扣上限 4 KB，其余字节即到即转；
   请求自带原生 `tools` 时完全不扫描。
8. 网关 fail-open：插件管线任何异常都不阻断转发，外部 API 可用性与零插件时等同。

## 11. 参考实现：现有功能 → 插件映射

规范完备性用这两个内置插件验证——它们迁移后，`ChatViewModel` 里对应代码全部删除：

### 便签插件（com.gguf.notes）—— UI + 中间件 + 工具，三形态齐全

| 现有实现 | 迁移到 |
|---|---|
| 系统提示词第 7 条（`<note>` 协议） | `tools: [notes.append]` 自动生成教学条款（标记升级为 `<tool name="notes.append">…</tool>`） |
| `noteIntentRe` / `isNoteEditRequest` 正则路由 | `route` 钩子 |
| `runNoteTool` / `runNoteOp` 两阶段管线（json_schema 受限解码） | `handle` + `gguf.llm.chat({json_schema})` |
| `applyModelNotes`（提取标记、替换成确认条） | `gguf.hooks.tool` + notice 通道 |
| 便签拼进首条 system | `context.head` |
| 便签内容 / 修改历史（100 快照） | `gguf.storage`（按 sessionId 分键；升级时宿主做一次性数据迁移） |
| 门户「便签」选项卡 UI | `ui.html`（`gesture: top [0.25,0.75]`） |
| scope / 权限 | `["local"]`（便签按会话，外部请求无会话）；`llm, chat:read, chat:route, chat:context, chat:annotate` |

### 简单记忆插件（com.gguf.memory）—— UI + 中间件，对外生效的中间件范例

| 现有实现 | 迁移到 |
|---|---|
| BM25-lite 检索（`MemoryIndex`） | service.js 内纯 JS 实现（词法算法无平台依赖） |
| 溢出窗口旧消息的回忆注入 | `context.tail`（空 = 零注入，保持现有快路径语义） |
| 读取被裁剪的旧消息 | turn 里由宿主给出溢出消息集（本机按会话窗口；外部按本次请求超预算裁剪的部分） |
| UI | `ui.html`：展示本轮召回了哪些片段（调试/可观测） |
| scope / 权限 | `["local","external"]`——外部客户端的超长对话同样被裁剪 + 检索回忆；`chat:read, chat:context, chat:external` |

> 注：消息窗口预算与裁剪（`winStart`）仍属宿主职责——它是上下文管理的核心，
> 随上下文组装一起迁入网关（§6.8），不是插件。插件只拿到「哪些消息已溢出窗口」
> 的事实并决定注入什么。

### 迁移终态

- **ChatViewModel 零插件逻辑**：便签路由/两阶段管线/`<note>` 提取/BM25 注入/窗口
  裁剪全部移出。它只剩：消息状态、SSE 流式客户端（带 `X-GGUF-Session` 头 +
  `gguf_ts` 字段）、解析 `gguf.notices` 渲染确认条、HTML 预览提取、会话持久化。
- **会话标签（tags）留在宿主**：它服务历史抽屉的智能分组，是会话元数据而非插件
  数据；编辑入口从便签选项卡迁到历史抽屉。
- **保持内置（不插件化）**：HTML 预览浏览器（与流式解析强耦合）、上下文组装与
  KV 缓存策略（网关宿主中间件）、左右抽屉（历史会话 / 模型配置）。

## 12. 版本与兼容

- `apiVersion` 不匹配（插件要求 > 宿主提供）→ 拒绝启用并提示升级 App。
- 宿主升级桥接口：只增不改（新方法/新钩子），破坏性变更递增 `apiVersion`
  并保留上一版兼容层至少一个大版本。
- manifest 未知字段一律忽略（向前兼容）。
