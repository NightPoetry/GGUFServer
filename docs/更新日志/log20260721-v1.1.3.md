# 更新日志 2026-07-21 · v1.1.3（versionCode 14）

## 本版主题：插件系统演进为「切面微内核」（阶段 0–3，等价重构·行为不变·真机验收通过）

退一步问「宿主内核到底该有多小」。答案：**内核唯一的原语，是「在一小组具名切面
（join point）上注册处理器，并按预算/权限/熔断/fail-open 分发一次调用」**。UI、中间件、
工具、Skill、工作流全部降级成挂在切面上的插件；连「工具系统」本身也只是**认领某个
能力 type 的一等运行时插件**。加一种能力类型 = 加一个 runtime，内核一行不改。

这不是新设计，而是给现有实现**改名归类**——`Gateway.kt` 的固定流水线、`PluginRuntime.dispatch`
的分发、`PluginManifest` 的形态字段，本就是「切面被写死」的样子。本版把切面显式命名出来，
让内核对「有哪些切面、每个切面挂了谁」无知。**§10 八条红线、§6.1 时序、§6.8 网关拓扑
原样继承**，只换一套坐标描述。设计全文见《工具插件规范》§13；迁移与真机结果见
`docs/切面微内核迁移进展.md`；演进前基线已打 tag `pre-aspect-kernel-v1.1.2`。

### 三类切面（§13.1）

- **注册面**（声明"提供什么"）：`callable`（今 tools[]模型调 / messageActions[]用户点，按 type
  与调用者分）· `ui`（今 ui.html面板 / settingsCard / card.html消息卡片，按挂载点分）·
  `capability`（今 provides[]，补丁式能力槽）。
- **管线面**（一次请求依次经过，零处理器即退化裸转发）：`route → curate → context → params
  → generate → stream → after`。
- **分发面**：`dispatch` —— 预算/权限/熔断/fail-open 都是它自带属性，`PluginRuntime.dispatch`
  是其手机端唯一实现。换平台（桌面端「小模型轮椅」）只换分发面实现，切面契约不变。

### 阶段 0：文档（§13）

《工具插件规范》新增 §13，把 §1–§12「一个插件三形态 + 一组钩子」统一收进切面微内核模型，
给出 4 阶段等价迁移路径。冻结 v1 原文快照 `docs/工具插件规范.原文快照-v1.1.2.md`。

### 阶段 1：抽出内核 AspectBus（等价重构）

新增 `plugin/AspectBus.kt`（零业务逻辑，纯词汇表 + 分发纪律）：

- **`Aspects`**：三类切面具名常量 + `PIPELINE_ORDER` + **每切面预算**（route 150ms / curate
  150ms / context 250ms / params 20s / handle 120s / tool 10s / afterReply 10s / continuation 90s）。
  预算属分发面自带属性，从 `Gateway` companion 上移至此、单一真源。
- **`AspectRegistry`**：把启用插件投影成「每个管线面挂了谁」（v1 绑定=钩子名/tools[]），
  收敛原先散在 `computePlan` 的 `active.filter{...}`。
- **`AspectBus`**：分发组合子 `routeUntilTakeOver`（route 语义）/ `parallel`（context 语义）/
  `serialForEach`（params 语义），封装共享 deadline 的预算算术；单次分发仍交
  `PluginRuntime.dispatch`。fail-open：返回 null 一律当「无返回」。

`Gateway.computePlan` 改为经 `AspectRegistry` + `AspectBus` 编排——**顺序/预算/fail-open/
零插件快路径逐字节等价**，仅收敛编排。

### 阶段 2：工具系统收敛为内置 `type:tool` 运行时插件（等价重构）

新增 `plugin/ToolRuntime.kt`：

- **`CapabilityRuntime`** 接口 = 原生运行时插件契约（`type` + `callablesIn` + `teachingClause`）；
  **`Runtimes`** 注册表 = 内核认识的运行时集合。
- **`ToolRuntime(type:tool)`**：把原先散在 `Gateway` 的三段收敛成一处——`teachingClause`
  （`<tool>` 教学/curate·context 面）、`makeScanner`（stream 面）、`execute`（`hooks.tool`
  执行 + notice/card/after 面）。`ToolTagScanner` 原样迁入（逐字节不变，零标记泄漏核心）。
- **`Gateway` 去特例化**：`applySystemSuffix` 迭代 `Runtimes.all` 拿教学条款；relay 用
  `ToolRuntime.makeScanner/ownerOf/execute` + `ToolCall/ToolOutcome`。流循环结构不变、行为等价。
- **「加一种能力类型 = 往 `Runtimes.all` 加一个 `CapabilityRuntime`、内核不改」至此为真、可复用。**

### 阶段 3：curate 切面落地 + generate 显式化（默认等价）

- **`curate` 面**（§13.4，按需给小模型露 callable）：`manifest` 认 `curate` 钩子（→`chat:context`
  权限）；`computePlan` 在 route 与 context 之间串行分发 curate（预算 150ms、快判定禁调 LLM），
  各处理器 `expose[]` 取并集算出本轮 `exposure`；`CapabilityRuntime.teachingClause(exposure)`
  据此逐 callable 收窄。**无插件声明 curate → `exposure=null` = 全露 = 逐字节等价 v1**——
  「小模型只看到相关工具」的行为增益要等某插件真正注册 curate 处理器时才发生（未来功能）。
- **`generate` 显式化**：takeOver 分支 = 用插件 handle **替换**默认 generate；默认分支 =
  forwardBody 交默认 generate（转发内部 llama-server）。命名归位，无行为改动。

### 架构红线（本版全部继承、未破坏）

- **零启用插件（或都无 hooks）→ `hasAnyMiddleware()=false` → 不解析请求体的纯转发**：切面模型
  里就是「管线面处理器集为空 ⇒ 只跑默认 generate」。
- **`head` 注入字节稳定 / `tail` 空即零注入**：`assembleWindow`（窗口裁剪）未动。
- **fail-open**：`AspectBus` 组合子对 `dispatch` 返回 null 一律当「无返回」；`PluginRuntime.dispatch`
  未改。管线所有处理器失效 = 裸流式透传。
- 现有 manifest 字段 / 钩子名 / 桥接口 / 内置插件 assets 全部不变（`apiVersion` 仍 1）。

### 真机验收（Redmi ruby 22101316C，MiniCPM5-1B-Q8_0，2026-07-21）

分支 debug 包 `install -r` 覆盖基线（同签名、数据/模型/51 会话全保留），启用
linemem/params/notes 等中间件（`hasAnyMiddleware=true`，管线真正跑到），经 `adb forward`
从 Mac curl 网关。

| 验收项 | 结果 | 证据 |
|---|---|---|
| AspectBus 管线（context 并行 / params 合并 / 顺序 / 预算） | ✅ | `GGUF-gw`：`context notes/linemem`、`params temperature=0.7 dry=0.8`、`tail 零注入` 多次复现 |
| route 接管 = 替换 generate | ✅ | 「帮我记一下:周五要交房租」→ 正文空 + `notices:[已记入便签:周五要交房租]` |
| **KV 前缀缓存字节稳定**（最关键红线） | ✅ | 同请求两发 `prompt_n` **28 → 1**（第二发只重算 1 token） |
| curate 默认全露注入教学 | ✅ | 本机 prompt 164 vs 外部 14 = **+150 token**（`<tool>` 教学 + systemClause） |
| 外部路径 + 流式扫描器零泄漏 | ✅ | 4 次流式 `grep <tool` 全 0、`[DONE]` 正常 |

两项如实标注（非本次改动的正确性风险）：扫描器「吞标记」路径未现场触发（1B 自发吐 `<tool>`
不可靠，故走 route+handle 确定性；该段为逐字迁入的原代码）；fail-open 为结构性已证、未做
现场故障注入。
