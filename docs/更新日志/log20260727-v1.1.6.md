# 更新日志 2026-07-27 · v1.1.6（versionCode 17）

## 本版主题：把「失败路径」当成一等公民——成建制找同类缺陷 + 第一次量 curate 的判定质量

v1.1.5 修的两个缺陷有个共同点：**正常跑一百遍都遇不到，一遇到就是整段 prefill 重算或插件永久失灵**。

## 一、定向审计：5 个失败路径缺陷

病型提炼成三类：**A** 逐轮可变的运行结果影响了本应字节稳定的东西；**B** 瞬时/无辜的失败被记成
持久惩罚，或真故障被静默吞掉；**C** 能力静默丢失（无日志、无提示，且不属有意的 fail-open）。

### 1（A+C）context 插件一超时，它的 head 就整段消失

`applyContext` 里一句 `r ?: continue`：某个 context 插件本轮没在 250ms 内返回，它的 head 就不进
首条 system 了。后果有两层——首条 system 的字节随「这一轮它快不快」抖动（KV 前缀失效，抖出去
那轮和抖回来那轮各重算一次整段 prefill），以及模型这一轮**凭空少掉人设**（sysprompt）或**长期记忆**
（linemem / heavymem），而日志里只有一行 debug。

代码注释原本写着「head 要求逐轮字节稳定——插件自己保证」。但**能把 head 抹掉的是宿主的 250ms
超时，插件无从保证**：契约把责任推给了做不到的一方。

**修法**：宿主记住每个插件**上一轮成功给出的 head**，本轮没返回时顶上（成功返回空串也照记——
那是它主动说「我这轮没有 head」），顶用时写进运行日志。复用是安全的：head 按契约本就该逐轮
一致，上一轮的值正是它这一轮应该给的值。`tail` 不顶——它本就逐轮可变，丢了不动前缀，顶上反而
可能把过时的回忆塞给模型。

### 2（B）串行面的共享预算没有下限，排在后面的插件被饿死并被记成「坏了」

`route`/`curate`/`params` 都是串行分发、**共享**一个 deadline，原实现只有 `remain <= 0` 才停。于是
第一个吃掉 140ms，第二个拿到 10ms——而一次分发的固定开销是「切主线程 → `evaluateJavascript` →
JS 执行 → `respond` 回程」两跳 looper，10ms 派下去必然超时。**超时会被记进熔断账本，连续三次
把插件永久旁路，且熔断状态落盘。**

今天就有现成的两人共享面：便签和朗读都登记了 `curate`、共享 150ms，顺序固定 ⇒ **每次被饿死的
永远是同一个**。

**修法**：加 `MIN_VIABLE_BUDGET_MS = 40`，剩余预算低于它就**根本不派**——不派就不会记成它的错。
**被同面的前一个处理器饿死 ≠ 这个插件坏了**，与 v1.1.5 那条「没准备好 ≠ 坏了」是同一条道理。

### 3（C）承上：被饿死的 curate 处理器，它的工具本轮被藏起来

纪律 3 说「登记了却没表态（异常/超时）≠ 弃权」，理由是「插件坏了它的 `tool` 钩子同样跑不了」。
但**被饿死的插件没坏，它连开口的机会都没有**。真实后果：用户说「用语音说：你好」，而 tts 恰好
排在后面被饿死 ⇒ 暴露集为空 ⇒ 这一轮一条工具教学都不注入 ⇒ 语音功能静默失效，模型压根不知道
`tts.say` 存在。

**修法**：内核区分三种情况，规范 §13.4 纪律 3 补了对照表——

| 情况 | 判给 | 理由 |
|---|---|---|
| 派下去了，它自己抛异常/超时 | **表态失败**（藏工具） | 它坏了，`tool` 钩子多半也跑不了 |
| 未就绪 / 预算见底没派到 | **弃权**（工具照露） | 它没坏、也没机会说话 |
| 压根没登记 curate | **弃权**（原语义） | 不参与决策者不该被决策伤害 |

### 4（C）`GATEWAY_HOOKS` 漏了 `curate`

一个**只登记 curate** 的插件（不提供工具、只决定本轮该露别家的哪些能力——正是 §13.4 收窄语义的
典型形态）会被判成「不是中间件」：要么整条管线走零插件快路径根本不执行，要么被 `activePlugins`
过滤掉。两种情况都是零日志、零提示，管理页还照常显示它「已启用」。今天内置的 tts 侥幸没踩到，
是因为它另有 `tools` 撑着——**它是被 tools 救的，不是被 curate 救的**。

### 5（C/B）`reconcile` 与 `destroyService` 的 TOCTOU

`reconcile` 跑在 `Dispatchers.Default`，而 `destroyService` 只把 `serviceViews.remove` post 到主线程。
「禁用 → 立刻重新启用」时，reconcile#2 看见旧条目还在、以为无需重建，随后主线程才把它销毁——
终态是「插件已启用、未熔断、管理页一切正常，但没有 service WebView」。此后每次 dispatch 都静默
返回 null：**不记错、不进熔断、连日志都没有**，工具"点了没反应"。

**修法**：摘表同步做、只把销毁 post 出去；`dispatch` 找不到 WebView 时补一行 warn（不计熔断——
那不是插件的错）。

## 二、curate 快判定：第一次量，发现方向反了

curate 上线以来只有 8+8 条手挑的冒烟样例，从没量过判定质量。建了带标注的语料一量：
**便签 recall 48%、precision 100%**——过严，与规范「宁可判宽」的取向正好相反。

代价是不对称的：**漏判是能力静默消失**（用户说了件该记的事，模型手里根本没这个工具，无任何日志），
**误露只是白花约 40 token 的教学条款**。

- **便签 1.0.2 → 1.0.3**：判定从「显式记录词 ∨（时间词 ∧ 承诺动词）」改成「**一个正信号 + 一道
  否定闸门**」。闸门挡掉提问/指使干活（「明天天气怎么样」有时间词但不是在交代事情）；正信号有
  四个：①显式记录词（并把「记得帮我买牛奶」的祈使义与「我记得你说过」的回忆义分开）②具体钟点
  或日期 ③时间词 ∧ 承诺动词（动词表补齐 交/签/接/休假/搬家/还款…）④耐久事实（密码/号码/位置/
  过敏/尺码/邮箱，以及形似凭据的串）。
- **朗读 1.1.3 → 1.1.4**：补「用声音 / 发个语音 / 念出声」等同义说法；「说出来」加伴随词闸门
  （想法/不好意思/憋…）——两条误露都出在它的表达义上。

`scripts/check-plugins.js` 的 curate 段随之从冒烟测试升级成**语料 + 指标**：43 + 27 条带标注样例
逐条断言，打印 recall/precision，并加一道 `recall ≥ 90%` 的硬门（漏判是第一指标）。

### 同时诚实记下天花板

上面那份语料是「先写语料、再调正则」调出来的，天然乐观。事后另写了一份**没参与调参**的泛化集：

| | 调参集 | 泛化集（未参与调参） |
|---|---|---|
| 便签·旧规则 | 48% | **0%** |
| 便签·新规则 | 100% | **42%** |
| 朗读·新规则 | 100% | 80% |

改进是真的（0% → 42%），但 42% 也说明：正则吃得下**结构化信号**（日期、钟点、凭据、显式词），
吃不下**语义判断**（「我答应了周六去帮忙搬东西」值不值得记）。泛化集以**只报告、不断言**的形式
进了仓库，并附警告：**不要为了提高它去调正则**，一调它就变成第二份调参集。

语义那半边在手机上短期无解——curate 是请求路径同步点、禁止调 LLM（只有一个 llama-server 实例，
在这里调模型会占住马上要用来生成回复的引擎）。规范 §6.14 记下了方向：**把判断挪出请求路径**，
回合结束后在 `after` 面判一次「刚才那句值不值得记」，命中就出角标让用户一键记入——漏判从
「静默消失」降级成「事后可补」，且完全不动 KV 前缀。属未来工作。
