# 更新日志 2026-07-27 · v1.1.10（versionCode 21）

## 本版主题：修「乐句」插件三处真机缺陷——用户说「它对自己已有的插件好像没有感觉」

v1.1.9 刚把乐句插件做出来，用户一上手就撞到：**让它创作音乐时，它像根本不知道自己有这个插件**。
翻设备上那条会话看到实况：

```
user:      write a midi melody            → 正常出了乐句卡片
user:      帮我写一个悲伤的调              → 模型反问「你想创作悲伤的旋律吗？歌词内容是什么？」
user:      使用工具                        → 模型开始介绍 MuseScore / FL Studio / 在线音乐生成器
```

三处缺陷，都是我自己写的语料想不到、只有真人用才会撞出来的。

## ① 音乐意图漏判：只认「曲」，不认「调」

`musicRe` 认的是「曲 / 旋律 / 乐句 / melody」，而用户说的是「一个悲伤的**调**」（曲调、调子）。
既不接管、也不露工具，模型手里什么都没有，只能自己发挥去反问。

补上：`调 / 调子`、`谱…曲`、`伴奏`、`主旋律`、`背景音乐 / BGM`。
「调」的非音乐义极多，所以带否定预查挡掉——**调用 / 调整 / 调试 / 调查 / 空调 / 语调 / 调休 / 调色**
等 30 余个后缀，语料里逐条钉住负例。

「使用工具」这类祈使本身没有音乐词，但在**刚出过乐句的会话**里它就是「用你那个作曲工具」——
挂到与续写同一道门上（下面 ③ 的会话标记），所以不会在别的语境里劫持整轮。

## ② 情绪夹取被「major」里的 m 骗过

这个最隐蔽。判定「模型给的调号是不是小调」用的是 `/m|min|小调/i.test(key)`——
**「C major」里有个 m**，于是被判成「已经是小调」，情绪夹取整段跳过。结果：

> 给你写了一段：**C 大调**，76 BPM，**悲伤**，…

速度夹对了（76），调式完全没夹——「悲伤」配了大调。同一个错在两个地方还有第二遍：
`parseKey` 与表头捕获也用 `(m|min|minor|小调)?`，所以 `Cmajor` 会被**解析成 C 小调**。

改成：削掉音名后先排除 `maj / 大调`，再认 `m / min / minor / 小调`，三处统一走这一个判定。
14 种写法（`C` / `C major` / `Cmajor` / `C-major` / `Cmaj` / `C 大调` / `Cmin` / `A小调` …）
在悲伤与欢快两个方向上双向夹取全部正确，已进语料。

## ③ 续写竞态：上一轮的状态还没落盘，下一轮就到了

「帮我写一个悲伤的调」紧接着「使用工具」，第二轮赶在 `storage.set` 落地之前到达，
`prev` 读成空 → 当成新曲子处理 → 调、速度、情绪全变（Am 小调 76BPM 悲伤 → G 大调 104BPM 无情绪）。

改成**同步内存副本 + 异步落盘两条**：内存那份下一轮立刻读得到，落盘那份留给 service WebView
重建后接着用。（与 `pieceSessions` 同样按会话记、有界。）

## 真机复现用户原话

| 输入 | 修前 | 修后 |
|---|---|---|
| 帮我写一个悲伤的调 | 模型反问「你想要什么风格」 | **Am 小调，76 BPM，悲伤**，6 小节 |
| 使用工具 | 介绍 MuseScore / FL Studio | 接着上一段又长了一节：Am 小调 76 BPM 悲伤，**16 小节 / 0:24** |

| 帮我调用这个接口 | — | 不被劫持（正常回答接口问题） |
