# 更新日志 2026-07-27 · v1.1.9（versionCode 20）

## 本版主题：第 11 个内置插件「乐句」——让模型作曲，端上合成播放

用户要的是「MIDI 组件：模型能调用它生成音乐，并且以特殊的 UI 对话框展示，与聊天的一致性足够好」。
做出来是 `com.gguf.midi`（乐句，1.2.4）：一条**可播放的乐句卡片**——点按播放/停止、长按看音符、
钢琴卷帘 + 播放头 + 时长，视觉与语音卡片同一套语言。声音是**端上合成**的（Web Audio 振荡器 +
包络 + 逐轨混音），完全离线、不联网、不下载音源、**不需要任何宿主改动或新桥接口**。

## 设计：模型出创意的最小单元，确定性的活全交给 JS

沿用本项目一贯的路子。分工是：

| 谁 | 干什么 |
|---|---|
| 模型 | 一个 4 小节片段（8～16 个音）+ 一行播放顺序 + 情绪/调/速度 |
| JS | 宽容解析（音名 `C4 E4 G4` 与简谱 `1 2 3` 都认）· 换算成 MIDI 音号 · **按调式自动配低音与和声** · 三轨音域折叠 · 多乐器音色 · 逐轨混音 + 软限幅 · 钢琴卷帘 · 滚动预排播放 |

**为什么叫 MIDI**：音符模型就是 MIDI 的语义（音高 0–127、力度、以 tick 计时长），卡片里的合成器
只是它的一个播放后端。诚实标注：本版**不导出 .mid 文件**（WebView 里存二进制没有好通道），
但数据模型是 MIDI 的，将来加导出不用改契约。

### 长曲子靠「片段 + 编排」，不靠让模型一路写下去

1B 写 8 个音是可靠的，写 64 小节是不可能的。但音乐本来就是**重复与变形**：

```
tempo:100 key:Am
inst: melody=bell bass=bass
mix: melody=0.8 bass=0.5
pat A: A4 C5 E5 - | G4 B4 D5 -
pat B: F4 A4 C5 - | E4 G4 B4 -
bass A: A2 - E2 -
play: A A B A+12 A*3
```

`+12`/`-5` = 整段移调，`*3` = 重复。4 小节的片段就能排出几十小节。老格式（单行音符）仍然认。

> **一处设计冲突与它的解法**：音域折叠（把模型乱爬的八度收回舒适区）一开始放在展开之后，
> 结果把 `A+12` 这种**有意的移调**也压回原音区了。折叠改到「片段定义」阶段——它要规整的是
> 模型乱写，不该动编排决定。

## 三条真机逼出来的设计修正

### ① 1B 不吐工具标签，所以必须有确定性那条路

真机实测：用户说「写一段轻快的旋律」，curate 正确露了 `midi.play`、教学也注入了，
**模型却把音符写进了 ```midi 代码块而不是 `<tool>` 标签**——它懂格式、不懂调用协议。
这与项目里早就记下的结论一致（1B 自发吐 `<tool>` 不可靠，受限解码才可靠）。

所以走便签验证过的那条路：**代码路由（正则判意图）→ 模型只填几个受限的槽（json_schema）→
关键动作由 JS 完成**。工具标签那条路保留，给会用协议的模型。卡片经桥路径插入
（`gguf.card.post`）——因为接管的响应体只支持 `content`/`notice`，不支持卡片。

### ② 情绪可以点菜，乐理常识外置给代码

「写一首**悲伤**的曲子」——模型不需要懂「悲伤 = 小调 + 慢 + 弦乐」，**这是可以查表的常识**。
插件按情绪定调式/速度/音色，并把模型矛盾的取值夹回去：实测模型给「悲伤 + 140 BPM + C 大调」，
被改成 **Cm 小调 76 BPM**。支持悲伤 / 安静 / 欢快 / 紧张 / 抒情 / 激昂。

### ③ 长曲子靠多轮续写，不靠机械重复

用户的话：「不用奢求一次性生成超长音乐；可以多次生成，从而得到风格统一但富有变化的旋律。」
所以说「**再来一段**」时：沿用同调、同速、同音色（风格统一），只让模型写**一个新片段**
（富有变化），JS 接到已有编排后面并回一次主题。真机实测 10 → 20 → 32 小节。

**续写的接管门是「本会话刚出过乐句」的同步标记**（按会话记，不是记一个）——否则
「再来一段」在写文章的语境里会被整轮劫持（§6.2 route 的 precision 第一）。真机验证：
另一个会话说「再来一段」照常写文章、不被劫持。

## 四个「模型不靠谱」的兜底（都是真机踩出来的）

| 现象 | 兜底 |
|---|---|
| 模型在某个字符串里跑飞（`♯\b\bd♯\b\bd…`）撞 max_tokens，**JSON 断尾整份解析失败**（1/3 概率白给一轮） | schema 给字符串加 `maxLength`（语法层面就停得住）＋ 解析失败时**按字段抢救**。修后首轮 4/4 成功 |
| 三次问「悲伤」给出**三次一模一样**的曲子——模型在照抄提示词里的示例音符 | 示例**轮换**（5 组不同调不同走向）＋ 明说「不要照抄示例里的音」。修后 3 首各不相同 |
| 续写时模型交白卷（2 次遇到 1 次） | 拿主题做**确定性变奏**（移调/逆行轮换）接上，并在回复里如实说明「这段是拿主题做的变奏」；首轮没主题可变才真的空手 |
| 模型一路往上爬三个八度（`C4 … B6 C7 D7`），听着像音阶练习 | 音域折叠（只动八度、不动音名，调性与轮廓不变） |

## 顺手补的一条宿主单测（本次真踩到）

`BuiltinManifestTest`：**所有内置插件的 manifest 必须能过 `PluginManifest.parse`，声明的入口文件必须存在**。
起因是 `PluginStore.bootstrapBuiltins` 里 `runCatching { releaseBuiltin(...) }` + `releaseBuiltin` 内部
`?: return` 是**两层静默**——manifest 有一个字段写错，表现就是「插件改了却没生效」：assets 里明明是
新版本，设备上还是旧文件，零日志零提示。这次为定位它花了不少时间，现在编译期就能发现。
