# 更新日志 2026-07-27 · v1.1.7（versionCode 18）

## 本版主题：route 接管判定收紧——误接管是插件体系里最严重的失败模式

v1.1.6 把「带标注语料 + 指标」这套方法用在了 curate 上。本版把同一套方法用到 `route` 上，
因为 route 判错的后果**比 curate 严重一个量级**：

| | 判错的代价 | 第一指标 |
|---|---|---|
| `curate` | 多花或少花几十 token 的教学条款 | **recall**（漏判＝能力静默消失） |
| `route` | **整轮被劫持**——用户问一个问题，回复被整个替换成插件的产物；编辑类接管还会去改用户真实的便签 | **precision**（宁可漏接管） |

一量就见血：**误接管率 31%（4/13）**。

## 四条误接管，全是同一个毛病：把「谈论便签」当成「操作便签」

原判定是 `s.indexOf('便签') >= 0 && /改|更新|替换|换成|删|去掉|清空/.test(s)`——
「句子里有『便签』」∧「句子里有编辑动词」，而**两者可以隔着十万八千里**：

- 「便签这个功能怎么用？我想**改**一下我的工作流」
- 「帮我把这段代码**改**一下，顺便讲讲便签插件的原理」
- 「你觉得便签和备忘录哪个好用？我在考虑**换成**印象笔记」
- 「便签的数据存在哪里？误**删**了能恢复吗」

四句都会被整轮劫持进便签编辑流程——而那个流程会跑两段式 LLM 管线，**去改用户真实的便签**。

**收紧办法不是加否定词表**（「谈论」的说法列不完），而是要求**动词与便签在句法上真的挨着**：

- ①「（把）便签（里/的）（第N条/全部/内容）+ 动词」
- ②「动词（+掉/一下/我的）+ 便签」
- ③「第N条（便签）+ 动词」

并保留「必须提到『便签』」这个硬前提——只说「把第三条删了」不接管，那多半指模型刚列出的清单。
（收紧过程中我一度放宽了这一条，实测意识到它与「precision 第一」自相矛盾，当场收回。）

结果：**调参集与未参与调参的泛化集，双双 precision 100% / recall 100%。**

## 顺带记下一条经验：句法判定能靠正则，语义判定不能

同一套标注方法、同一个插件，两个判定的泛化能力差得极远：

| 判定 | 判的是什么 | 调参集 | **泛化集（未参与调参）** |
|---|---|---|---|
| `route` | 「这句话是不是在操作便签」——**有语法结构** | 100% | **100%** |
| `curate` | 「这句话值不值得记」——**要理解意思** | 100% | **42%** |

**判定形态决定了正则的天花板。** 别指望往同一个正则里堆词表能把语义那半边补上——route 这种
句法判定收紧一次就到顶了，curate 那种语义判定堆到 42% 就再也上不去（v1.1.6 已记，见规范 §6.14）。
这条写进了规范 §6.2，供后来人判断自己面对的是哪一类。


**真机**（ruby `22101316C` · MiniCPM5-1B-Q8_0，便签插件 1.0.4）：

| 输入 | 结果 |
|---|---|
| 便签这个功能怎么用？我想改一下我的工作流 | ✅ 正常模型回复（讲便签怎么用），`notices=None`——**未被劫持** |
| 帮我把这段代码改一下，顺便讲讲便签插件的原理 | ✅ 正常模型回复（改代码 + 讲原理）——**未被劫持** |
| 便签的数据存在哪里？误删了能恢复吗 | ✅ 正常模型回复——**未被劫持** |
| 把便签第二条改成周六 | ✅ 仍然接管，走编辑流程（本会话便签为空 → 「便签目前是空的，没有可修改的内容。」） |
