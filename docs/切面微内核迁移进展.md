## 真机验收红线（务必逐条过；这些是 Claude 无法自测的部分）

在真机装上 `aspect-microkernel` 分支构建的 debug 包后：

1. **零插件裸流式**：禁用所有插件，本机聊天 + 外部 curl 各发一轮。要求：正常流式、
   `logcat GGUF-gw` 无插件管线日志、重复请求 `cache_n` 不回退（前缀 KV 命中，字节稳定）。
2. **§10 八条红线全绿**：尤其 route 150ms / context 250ms 预算、SSE 只扫工具标记、
   fail-open（下条）。
3. **fail-open 回归**：启用便签插件后，杀掉其 service WebView（或塞一个必超时的 route）——
   外部 API 仍能正常流式（等于零插件透传），不卡死。
4. **§11 参考实现三形态**：
   - 便签：中文 curl 触发 route 接管写便签 + 英文真机 UI 确认条；`<tool name="notes.append">`
     标记零泄漏（流里看不到标签）、notice 走收尾 chunk。
   - 记忆（对外中间件）：外部超长对话被裁剪 + BM25 召回 + tail 注入、模型答对。
   - 朗读：消息角标朗读 + `tts.say` 工具→语音气泡卡片自动播放。
5. **采样参数导演（params 面）**：参数导演插件启用时，写作/代码/闲聊三档仍生效；
   受限解码请求（json_schema）仍被判定保护中和惩罚采样 + 跳过 params。
6. **curate 默认全露**：启用任意带 tools 的插件，确认 system 里工具教学条款与迁移前**逐字**
   一致（因无插件声明 curate）。可选：临时给某插件 manifest 加 `"hooks":["curate",…]` +
   service 里 `gguf.hooks.curate` 返回 `{expose:["notes.append"]}`（并加 `chat:context` 权限）
   验证只教被暴露的工具——但这是新能力验证，非回归。

> 对比基线：同一测试在 `git checkout main`（tag `pre-aspect-kernel-v1.1.2`）的构建上跑一遍，
> 两边 `logcat GGUF-gw` 的 context 长度、tail 注入字数、cache_n 应一致。

## 阶段 3.5：curate 真正开始收窄（v1.1.4，2026-07-25）

阶段 3 只是把 join point 挖出来了（`exposure=null`=全露=等价 v1）。本次让它真的收窄，
并在过程中补掉三个坑：

| 改动 | 说明 |
|---|---|
| **SDK 补 `gguf.hooks.curate`** | 阶段 3 只做了宿主侧，`gguf-sdk.js` 的钩子表里压根没有 curate → JS 侧一直是 `undefined`，插件根本注册不上。**"没有一个插件真的用过"的代价**，补上 |
| **便签 / 朗读各登记 curate** | notes 1.0.2：隐含记录意图（记录/提醒/待办，或"时间词+承诺词"）才露 `notes.append`；tts 1.1.3：用户要求"读出来/用语音说"才露 `tts.say`（新增 `chat:context` 权限） |
| **弃权豁免（内核）** | 暴露集 = 各 `expose[]` 并集 **∪ 没登记 curate 的插件的全部 callable**。否则装一个带 curate 的插件会静默掐掉第三方插件的工具 |
| **动态注入位（内核，KV 红线）** | 有人表态 → 教学条款成了逐轮可变内容 → 从首条 system 改插到「末条用户消息之前」。否则每次意图切换整条 prompt 从第一个 token 作废，手机上要重算整段 prefill，省下的百来 token 远不够抵。无人表态时位置不变、逐字节等价 v1 |
| **fail-open 成为内核自带属性** | `AspectBus` 三个组合子 + 结果消费都包了 guard：处理器抛异常一律当"本轮无返回"（`CancellationException` 原样上抛，不吞取消） |

**新增的自动化验证**（正是过去只能靠真机撞运气的部分）：

```sh
"$GRADLE" -p android :app:testDebugUnitTest   # 19 项：AspectBus 分发纪律/curate 语义 + ToolTagScanner 零泄漏
node scripts/check-plugins.js                 # 26 项：curate 判定样例 + heavymem 计算两段式（跑真 service.js）
```

`ToolTagScannerTest` 覆盖的正是真机验收里那条 ⚠️「吞标记路径未现场触发」——1B 不肯自发吐
`<tool>`，但逐字符跨分片喂进扫描器这件事在 JVM 上可以钉死。`AspectBusTest` 同理覆盖了
⚠️「fail-open 未现场注错」。

### v1.1.4 真机验收结果（2026-07-25 · ruby 22101316C · MiniCPM5-1B-Q8_0 · 全绿）

`install -r` 覆盖 v1.1.3（同签名，数据/模型/会话全保留），启用 linemem/params/notes/tts/voicelab，
经 `adb forward` 从 Mac curl 网关。测量手段：响应体的 `timings.cache_n` / `prompt_n` /
`usage.prompt_tokens` + `logcat -s GGUF-gw`。

| 验收项 | 结果 | 证据 |
|---|---|---|
| curate 收窄可见 | ✅ | 「今天天气真不错」→ `exposure=(空)` 且**无**教学注入；「我下周三要去体检」→ `notes.append` + `动态教学注入 125 字`；「读一下这段」→ `tts.say` + 202 字 |
| **KV 前缀缓存不因收窄回退**（最关键） | ✅ | 同一段 4 条消息的固定历史：闲聊结尾 `cache_n=180 prompt_n=1`；换成收窄结尾 **`cache_n=164 prompt_n=87`**（历史 164 token 全保住，只重算教学+末句）；收窄轮重复发 `cache_n=250 prompt_n=1`；再换回闲聊结尾 `cache_n=164 prompt_n=17`。**教学若进 head，这里会是 `cache_n=0 prompt_n=250+`** |
| **收窄的实际收益** | ✅ | 同一句话的 `prompt_tokens`：闲聊轮 **167 → 17**（−90%）；「我下周三要去体检」168 → 89；「读一下这段」→ 143（tts.say 的 description 长） |
| 弃权豁免 | ✅ | `run-as` 临时把 tts 的 `curate` 摘掉（版本改高防被 assets 覆盖）→ 同一句话 `exposure=notes.append,tts.say`——tts 弃权，工具照露 |
| 老路径逐字等价 v1.1.3 | ✅ | 便签+朗读都改成弃权（= 无人登记 curate）→ `curate` 日志 0 条、`prompt_tokens=167`（教学回 head、全露） |
| **fail-open 现场注错**（v1.1.3 遗留的 ⚠️） | ✅ | 往 notes 的 `service.js` 尾部追加一个直接 `throw` 的 curate 钩子 → 连发 4 次（跨熔断阈值）**全部 HTTP 正常、模型正常回复**、`exposure=(空)`、`prompt_tokens=18` |
| 流式 + 收窄同轮 | ✅ | 94 行 SSE、`[DONE]` 正常、`grep '<tool'` **0**、正文完整（体检准备建议） |

> 崩溃插件的工具**不露**是有意的：登记了 curate 却没表态（异常/超时）≠ 弃权。插件坏了它的
> `tool` 钩子同样执行不了，这时候把工具教给模型只会让它调一个必然失败的东西。fail-open 保的是
> 「请求不阻断」，不是「工具一定露出」。
>
> 真机注错验证的是 **JS 异常 → SDK `respondError` → `dispatch` 记失败返回 null → 组合子当无返回**
> 这条完整链路；`AspectBus.guard` 兜的是另一层（dispatch 实现本身在 Kotlin 侧抛异常），由
> `AspectBusTest` 覆盖。两层防线各有单证。

**未验**：heavymem 1.0.6 的计算两段式与召回升序（当前设备未启用重型记忆插件，验证需配记忆模型 +
喂记忆 + 等闲置做梦抽条目）。JS 逻辑已由 `node scripts/check-plugins.js` 端到端覆盖
（意图判定、四种运算、脏数据剔除），真机待下次启用重型记忆时顺带确认。

**设备现状**：ruby 上装的是 v1.1.4 debug 包；测试中临时改过的 `com.gguf.notes`/`com.gguf.tts`
的 manifest 与 service.js **已还原并校验 md5 一致**。
