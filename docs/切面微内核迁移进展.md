## 真机验收红线（务必逐条过；这些是 Claude 无法自测的部分）

在真机装上 `aspect-microkernel` 分支构建的 debug 包后：

1. **零插件裸流式**：禁用所有插件，本机聊天 + 外部 curl 各发一轮。要求：正常流式、
   `logcat GGUF-gw` 无插件管线日志、重复请求 `cache_n` 不回退（前缀 KV 命中，字节稳定）。
2. **§10 八条红线全绿**：尤其 route 150ms / context 250ms 预算、SSE 只扫工具标记、
   fail-open（下条）。
3. **fail-open 回归**：启用便签插件后，杀掉其 service WebView（或塞一个必超时的 route）——
   外部 API 仍能正常流式（等于零插件透传），不卡死。
4. **§11 参考实现三形态**：
   - 便签：中文 curl 触发 route 接管写便签 + 英文真机 UI 确认条；`<tool name="notes.append">`
     标记零泄漏（流里看不到标签）、notice 走收尾 chunk。
   - 记忆（对外中间件）：外部超长对话被裁剪 + BM25 召回 + tail 注入、模型答对。
   - 朗读：消息角标朗读 + `tts.say` 工具→语音气泡卡片自动播放。
5. **采样参数导演（params 面）**：参数导演插件启用时，写作/代码/闲聊三档仍生效；
   受限解码请求（json_schema）仍被判定保护中和惩罚采样 + 跳过 params。
6. **curate 默认全露**：启用任意带 tools 的插件，确认 system 里工具教学条款与迁移前**逐字**
   一致（因无插件声明 curate）。可选：临时给某插件 manifest 加 `"hooks":["curate",…]` +
   service 里 `gguf.hooks.curate` 返回 `{expose:["notes.append"]}`（并加 `chat:context` 权限）
   验证只教被暴露的工具——但这是新能力验证，非回归。

> 对比基线：同一测试在 `git checkout main`（tag `pre-aspect-kernel-v1.1.2`）的构建上跑一遍，
> 两边 `logcat GGUF-gw` 的 context 长度、tail 注入字数、cache_n 应一致。

## 构建 / 部署 / 回滚

```sh
# 构建（分支代码）——需工具链
source /Volumes/SystemData/gguf-toolchain/env.sh
"$GRADLE" -p android :app:compileDebugKotlin        # 快编译门（Claude 已跑通）
./scripts/debug.sh                                  # 出 debug 包（注意：同版本号 1.1.2 会覆盖
                                                    # debug/ 里基线那份——如需保留基线包，先备份它）
./deploy.sh                                         # 装到 USB 手机（MIUI 凭据锁需先解锁）

# 回滚（任一）
git checkout main                                   # 或 git checkout pre-aspect-kernel-v1.1.2
tar xzf _代码备份_v1.1.2-切面微内核前_*.tar.gz        # 物理归档还原
```

⚠️ `scripts/debug.sh` 按当前 versionName(1.1.2) 命名，会覆盖 `debug/GGUF-Server-debug-1.1.2.apk`
（那是基线包）。真机对比测试前，建议先把基线 debug 包另存，或在测完分支后 `git checkout main`
重建基线包。发版时再按《打包流程》升 versionName/versionCode + 写 `docs/更新日志/`。
