# 架构与原理

## 1. 核心思路

在手机上提供 OpenAI 兼容服务，最省事、最稳的方式不是自己写推理引擎和 HTTP 服务，而是**复用 llama.cpp 的
`llama-server`**——它已经内建了完整的 OpenAI 兼容 API：

- `POST /v1/chat/completions`（支持流式 SSE）
- `POST /v1/completions`
- `POST /v1/embeddings`
- `GET  /v1/models`
- 以及 `/health`、`/props` 等辅助端点

所以本 App 的职责被压缩成两件事：

1. **管理模型文件**：用 Android 的 SAF（Storage Access Framework）让用户挑一个 `.gguf`，复制进 App 私有目录。
2. **管理服务进程**：把 `llama-server` 当子进程拉起、守护、停止，并把它监听的局域网地址显示出来。

## 2. 最关键的一环：怎么在 Android 上执行一个二进制

现代 Android（API 29+）有 **W^X** 限制：App 数据目录（`filesDir`、`cacheDir`）挂载为 `noexec`，
你把可执行文件拷进去也无法 `exec`。

唯一的例外是 **`nativeLibraryDir`**——即 APK 里 `jniLibs/<abi>/` 下的原生库在安装时被解压到的目录，它是可执行的。

因此业界通用做法（cloudflared、frp、各种把 CLI 塞进 App 的项目都这么干）是：

- 把可执行文件**改名为 `lib*.so`**（这里是 `libllamaserver.so`），放进 `jniLibs/arm64-v8a/`；
- 在 `AndroidManifest.xml` 设 `android:extractNativeLibs="true"`，并在 Gradle 里
  `packaging { jniLibs { useLegacyPackaging = true } }`，保证它被**解压成真实文件**（而不是压缩在 APK 内）；
- 运行时用 `context.applicationInfo.nativeLibraryDir` 取到路径，`ProcessBuilder` 拉起。

`llama-server` 依赖的共享库（`libllama.so`、`libggml-base.so`、`libggml-cpu.so`、`libggml.so`、`libmtmd.so`）
同样放进 `jniLibs`，并在启动子进程时设置环境变量 `LD_LIBRARY_PATH=<nativeLibraryDir>`，动态链接器就能找到它们。

对应代码见 `server/LlamaServerService.kt`：

```
val nativeDir = applicationInfo.nativeLibraryDir
val bin = File(nativeDir, "libllamaserver.so")
ProcessBuilder(bin.absolutePath, "-m", modelPath, "--host", "0.0.0.0", "--port", "8080", ...)
    .apply { environment()["LD_LIBRARY_PATH"] = nativeDir }
    .start()
```

## 3. 为什么用「前台服务」

一个长时间占用 CPU 的推理服务，如果放在普通后台，很快会被系统回收。所以用
**前台服务（Foreground Service）** + 常驻通知，并申请：

- `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_SPECIAL_USE`：声明前台服务类型为 `specialUse`（本地推理服务器）。
- `WAKE_LOCK`：`PARTIAL_WAKE_LOCK` 保证息屏后 CPU 不休眠。
- `WifiLock`（`WIFI_MODE_FULL_HIGH_PERF`）：保证 WiFi 不进省电断连，socket 不掉。
- `POST_NOTIFICATIONS`（Android 13+）：显示常驻通知。
- `INTERNET`：绑定 TCP socket 必需（普通权限，自动授予）。

进程生命周期在 `LlamaServerService` 里用一个 IO 线程读取 `llama-server` 的 stdout/stderr：
看到 `server is listening` 就把状态置为「运行中」；进程退出则清理唤醒锁、关闭前台、停止服务。
UI 与服务之间用单例 `ServerBus`（`StateFlow`）通信。

## 4. 模型导入

`ModelStore` 用 `ActivityResultContracts.OpenDocument()` 拿到 `content://` URI，
通过 `ContentResolver.openInputStream` 流式复制到 `filesDir/models/<name>.gguf`（边复制边回调进度）。
`llama-server` 用 `mmap` 加载该文件，内存占用随实际使用增长。

## 5. 数据流总览

```
用户选文件(SAF) ──► ModelStore.import() ──► filesDir/models/xxx.gguf
                                                    │
点击“启动” ──► MainViewModel.startServer() ──► LlamaServerService(前台)
                                                    │  ProcessBuilder
                                                    ▼
                                     nativeLibraryDir/libllamaserver.so
                                       -m xxx.gguf --host 0.0.0.0 --port 8080
                                                    │  监听
                                                    ▼
                    http://<手机局域网IP>:8080/v1/*  ◄── 同 WiFi 的客户端(OpenAI SDK/curl)
```

## 6. 已知取舍

- **CPU 推理**：默认 CPU 后端，兼容性最好。Vulkan GPU 后端在部分手机能提速但兼容性不稳，未启用。
- **arm64 only**：只打包 `arm64-v8a`，覆盖近年绝大多数机型，APK 更小。
- **指令集**：默认基线 `armv8-a` 保证不崩；可通过 `CPU_MARCH` 为新机型开 `dotprod/i8mm` 提速。
- **单模型**：一次跑一个模型。要换模型先停服务、选另一个再启动。
